### 최종 리뷰 보완

부모 검토와 같은 호스트의 별도 검토에서, 미저장 카드가 뜻/품사 필터에서 제외된 상태로 충돌하면 **현재 위치 저장**이 화면의 대체 카드 대신 제외된 ID를 저장하는 P2 결함 한 건을 확인했다. 표시 카드 ID를 명시적으로 전달하도록 보완했다. 회귀 검사는 수정 전 실패(종료 1), 수정 후 통과(종료 0)했으며 재조회 중 최신 이동과 원격 revision 재변경 보호도 확인했다. 외부 Claude Code CLI는 설치되지 않아 해당 추가 검토는 미실시다.

후속 광역 검토에서 세 가지를 추가 보완했다.

- 같은 브라우저의 다른 탭이 조회하거나 이전 요청을 마칠 때 최신 캐시를 덮던 결함을 수정했다. 다른 탭이 바꾼 미저장/저장 완료 캐시는 백그라운드 처리로 덮지 않으며, 새로 직접 이동한 경우에는 최신 선택을 기록한다. 수정 전 재현은 종료 1, 이후 단위/실제 두 탭 새로고침 복구는 종료 0이다. 별도 검토도 조회·늦은 성공·늦은 실패·새 이동을 재생해 확인했다. 첫 보완은 pending만 보호했으나 추가 검토에서 늦은 실패가 더 최신의 저장 완료 캐시를 덮고 오래된 초안을 자동 재전송할 수 있음을 발견해 보호 범위를 넓혔다. 이 경로도 수정 전 종료 1이며, 새로고침 후 GET만 수행하고 마지막 저장 위치/revision을 그대로 유지하는 회귀 검사를 추가했다.

- 로컬 built Worker 종합 검사: 빠른 이동/저장 중 닫기, 탭·새로고침·별도 브라우저 컨텍스트의 동일 계정 재개, 앞면·번호/경계·이미지 실패, 두 기기 모의 충돌의 양쪽 선택, 25초 시간 제한, 실패/커밋 후 응답 유실의 재조회, 최초 조회 실패 무쓰기, 제외 카드의 다음 유효 카드·빈 목록, 신규 계정 독립 위치와 이전 화면의 401/쓰기 중단.
- 320/390/1440px × 글자 100/200%, 44px 이동 버튼, 키보드·초점 복귀·axe를 확인했다. 카드를 옮겨도 브라우저 history 길이는 늘지 않는다. 계정 A의 기존 학습 문서·학습 revision·동일 시각에 만든 백업을 전후 대조했다. 401 거부 자체의 DB 무변경은 SQLite API 검사로 따로 확인했다.

## 초기 구동과 이미지 요청

기준 main 빌드와 최종 빌드에 각각 새 루프백 Worker·가상 D1을 사용했다. 동일한 0/365/1,825회차 자료, Chromium 390×844, CPU 4배 지연, 새 브라우저 컨텍스트/캐시 없음, 이미 준비된 Worker에서 조건별 3회씩 교대 측정했다. 느린망은 지연 150ms·다운로드 500,000B/s·업로드 125,000B/s다.

시간은 navigation 시작부터 ‘서버에 저장됨’ 화면과 두 번의 animation frame까지다. 외부 폰트는 양쪽 모두 차단했고, 그림은 동일한 검토 WebP 로컬 fixture를 사용했다. 실제 운영망·HTTP/2·콜드 Worker·iPhone 성능으로 일반화하지 않는다.

|---|---|---:|---:|
| 0 | 기본 | 1,194 [1,147–1,231] | 1,160 [1,133–1,188] |
| 0 | 느림 | 2,287 [2,266–2,290] | 2,305 [2,301–2,314] |

모든 표본에서 홈의 위치 GET/이미지 요청은 **0**, 이미지 인덱스가 든 JS도 미요청이다. 연습 진입 후 현재 그림과 다음 그림 **2장**만 요청했다. 새 위치 GET은 연습 진입 때 1회다. 기존 학습 스냅샷과 revision은 모든 비교 조건에서 보존됐다.

초기 JS 요청은 **15→16개**다. 홈 준비 시점의 same-origin Resource Timing `encodedBodySize` 합계는 **2,253B 증가**했다(탐색 HTML·헤더 제외). 0회차 444,785→447,038B, 365회차 613,678→615,931B, 1,825회차 1,258,107→1,260,360B다. 조건별 변동이 있고 각 3회 표본이므로 보편적 속도 개선이나 무회귀율을 주장하지 않는다. 이전 측정은 각 검증 JSON에 보존하고 위 수치는 광역 검토의 최종 캐시/초점 보완 뒤 재측정했다.

## 실패 이력과 확인 한계

- 기존 키보드 검사는 한 번 Tab 뒤 번호 입력 대신 ‘다음’을 눌러 통과할 수 있었다. 다음 버튼과 실제 입력란의 초점을 각각 확인하고 입력 후 번호 버튼 복귀를 검사하도록 보완했다.
- WebKit의 수업 이미지 검사는 React 갱신 전에 이미지 개수를 읽어 실패했다. 실제 이미지 제거/표시를 기다린 뒤 원래 개수를 검사한다. 백업 안전장치 검사는 테스트 상태 교체를 `flushSync`로 반영한 뒤 원래 비활성화/복원 무호출 조건을 검사한다. 제품의 수업/백업 코드를 바꾸지 않았으며 보완한 두 검사는 양 엔진에서 통과했다.
- 창 닫기 검사의 첫 실행은 문법 도움말 플래그 누락으로 시간 초과했다. 해당 검사에 필요한 문법·대용량 복원 플래그를 별도 로컬 Worker에 설정한 뒤 양 엔진에서 통과했다. 운영 플래그는 변경하지 않았다.
- 최종 재빌드 뒤 QA가 새 서버 메타데이터 작성 전에 이전 포트를 읽어 준비 검사에서 종료 1이었다. 새 서버의 루프백 응답 200을 확인하고 같은 검사를 다시 실행했다. 실패 로그는 보존했다.
- 기존 `state-roundtrip-qa.cjs`의 WebKit 실행에서 ‘다른 뜻 추가’ 버튼을 찾지 못하는 30초 시간 초과가 한 번 발생했고, 첫 PR 검토 당시에는 원인이 미확정이었다. 후속 조사에서 같은 증상의 클릭 누락과 폰트 부분 적용에 따른 행 이동을 재현해 QA를 격리한 뒤, 실제 앱도 별도로 수정했다. 위 실제 앱 후속 수정과 해당 JSON이 최신 근거이며 최초 실패 자체의 trace는 없다.
- Windows에서 실행 중인 미리보기가 `dist/client`를 잡고 있어 재빌드가 `EBUSY`로 종료 1이었다. 소유 서버를 종료한 뒤 재빌드했고, 이후 QA는 복사한 고정 빌드로 실행했다. 최종 빌드/QA 복사본 지문을 대조한다.
- 첫 종합 검사에서 ‘발음’과 ‘음성 도움말’ 두 summary가 잡혔다. 정확한 ‘발음’ 선택자로 고친 뒤 검사했다. 기대 동작을 완화하지 않았다.
- 로컬 Wrangler에서 **본문이 있는 PUT을 401로 거부한 뒤 연결을 재사용하면 다음 조회가 지연**되는 현상을 짧은 검사로 재현했다. 변경 전 main의 기존 `/api/state`도 `GET 200 → PUT 401 → 다음 GET timeout`이었다. 본문 취소만으로 해결되지 않아 그 변경은 제거했다. 중간에 Wrangler 종료도 관찰했으며 하위 구현 원인/운영 재현 여부는 미확정이다. 최종 브라우저 검사는 신규 계정 독립 위치를 먼저 확인하고 이전 계정 화면의 401/쓰기 중단으로 마친다. 이 로컬 연결 재사용 문제를 해결했다고 주장하지 않는다.
- 기존 SQL과 Git blob의 첫 원문 SHA 대조는 Windows CRLF/LF 차이로 실패했다. 파일을 수정하지 않고 Git의 실제 clean filter를 적용한 blob과 기존 schema 객체를 대조해 보존을 확인했다. 기본 폴더 파일은 원래 디스크 SHA 그대로 비교했다.
- 실제 iPhone Safari/홈 화면·VoiceOver, 운영 계정/운영 DB, 운영 AI·결제, 실기기 저장/재접속은 미검증이다. GitHub 원격 CI는 푸시 후 PR의 체크 기록으로 별도 확인하며 위 로컬 검사의 성공과 구분한다.

## 변경 경계와 운영 준비

기본 폴더의 기존 변경은 계획 작성 때의 18개에 계획/프롬프트 2개가 더해져 작업 시작 시 **20개**였다. 상태·경로·디스크 SHA를 전후 비교해 그대로 보존했다. 지정 이미지 worktree만 수정했으며 기본 폴더 브랜치를 전환하지 않았다.

기존 SQL/snapshot 10파일과 기존 journal 5항목을 유지했다. `db:generate`가 추가한 테이블 하나와 새 snapshot/journal 항목만 사용한다. `.openai/hosting.json`, 바인딩, 의존성/lockfile, 기존 학습 API·저장소·백업 소스는 Git 기준과 동일하다. 임시 DB마다 미적용 마이그레이션만 한 번씩 실행했으며 운영 DB에는 적용하지 않았다.

위험도는 중간이다. 위치는 학습 revision·성적·일정·백업과 분리된다. 위치용 계정 ID·카드 이동 이력을 진단에 추가하지 않는다. 향후 게시 때 기존 Sites 절차로 새 테이블 적용을 확인해야 한다. 롤백은 이전 앱으로 돌아가되 위치 테이블/데이터를 남기며 학습 기록을 복원하거나 DROP하지 않는다. 실제 운영 게시/롤백은 미실시다.

사용자의 후속 요청으로 커밋·푸시·PR 생성까지 진행하며, 병합·운영 배포·결제/공개 범위 변경은 범위 밖이다. [최초 구현 검증 JSON](releases/2026-10-17-image-practice-resume-verification.json)의 미커밋/미푸시 표시는 그 검증 시점의 기록이다. 최종 리뷰 후 증거는 [PR 검증 JSON](releases/2026-10-17-image-practice-pr-review.json), 원문 로그와 이전 실패는 Git 제외 `work/image-practice-resume/pr-review/`에 보관한다. 화면/측정은 `outputs/image-practice-resume/`, `outputs/word-image-full/`, `outputs/image-practice-performance/`에 있다.

후속 광역 검토의 최신 증거는 [광역 감사 JSON](releases/2026-10-17-image-practice-broad-audit.json)에 있다. 이번 원문 로그·실패 재현·성능 36표본과 고정 빌드는 Git 제외 `work/image-practice-resume/broad-audit/`에 보관한다. GitHub의 최신 커밋과 CI 결과는 [PR #39](https://github.com/zzocojoa/haru-word/pull/39) 본문/체크에서 별도로 확인한다.
