# T8.2·T15.2 교정 보류 응답 처리

AI가 원문의 문제를 지적하고 교정에 필요한 문맥을 요청하면서 교정문을 비워 두면, 로컬 후보는 응답을 형식 오류로 거절했다. 이 응답 형태를 기존 교정 보류 형식으로 처리하도록 판정 파서를 수정했다.

- 일반 문장 쓰기에서 전달하려는 내용이나 절의 연결 관계가 없으면, 기존 정책에 따라 두 판정을 유보하고 문맥을 묻는다.
- 시점이나 수량은 앱에 검토된 형태 오류 근거가 있는 경우에만 이 응답 형태를 받아들인다. 화면에 확인된 형태 오류와 질문을 보여주며 교정문을 비운다.
- 교정문 없이 질문도 빠진 응답, 근거가 확인되지 않은 시점 질문, 뜻만 불명확한 응답은 기존 검사를 유지한다. 답변·제목·명령으로 명시한 입력에는 일반 문장 쓰기의 보류 처리를 적용하지 않는다.

저장 필드와 제공자 요청 본문은 그대로다. 합성 응답으로 단어·문법 화면을 Chromium과 WebKit에서 각각 검사했다. 네 경우 모두 사용자가 요청 버튼을 누른 뒤 한 번만 제공자 경로를 실행했고, 문맥 질문을 표시했다. 교정문·적용 버튼은 없었다. 저장 영수증, 새로고침 후 표시, 단어 독립 회상과 문법 첫 답·관찰 기록을 확인했다.

최초 집중 검사에서 수용해야 할 두 그룹이 거절되는 것을 재현했다. 변경 후 관련 44개 및 전체 898개 검사가 통과했고 타입 검사·린트·빌드는 종료 코드 0이다. 린트에는 기존 경고 15개가 있다. 최초 브라우저 검사는 수업 이름을 잘못 지정해 시간 초과했고, 화면의 실제 수업 이름으로 다시 실행해 4/4를 확인했다.

별도 로컬 후보에 적용했다. 동결 평가 후보와 기준판의 지정 소스 및 서버 파일 지문을 대조했다. 실제 모델 호출, 운영 쓰기, 정식 예비평가 생성은 0회다.
