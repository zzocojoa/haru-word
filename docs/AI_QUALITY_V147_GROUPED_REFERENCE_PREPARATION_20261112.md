# T24.2·T24.3 남은 참조 검토의 묶음 요청 준비

현재 60문항 중 이미 실제 응답을 받은 첫 6문항을 분리하고, 남은 **54문항·두 모델씩 108판정**을 모델별 36문항씩 **3개 요청**으로 편성했다. 새 요청·응답 해석 도구의 로컬 검증을 마쳤다. 실제 모델 응답·입력 토큰 계산·키 읽기·예산 변경은 모두 0회다. 실행 수집기는 아직 없으며 이번 문서는 실행 승인 요청이 아니다.

최신 phase146 출처 보완 요청을 사용한다. 이 요청에는 phase137의 교체 2문항과 phase146의 출처 보완 16문항이 이미 반영돼 있다. 이전 phase127 파일을 현재 요청으로 잘못 사용하지 않는다. Noor 후속 검토 2개를 포함한 첫 6문항의 실제 응답과 보류 사유는 보존하며 중복 전송 목록에 넣지 않았다. 첫 6문항 중 작성 기준과 AI 판단이 다른 2문항도 해결된 것으로 바꾸지 않았다.

| 항목 | 개별 요청 | 묶음 초안 |
| --- | ---: | ---: |
| 남은 문항 | 54 | 54 |
| 문항별 서로 다른 AI | 2 | 2 |
| 판정 슬롯 | 108 | 108 |
| 모델 응답 / 입력 계산 횟수 | 108 / 108 | 3 / 3 |
| 계산료 여유 | US$3.780000 | US$0.105000 |
| 실제 입력 토큰·총비용 측정 | 미실시 | 미실시 |

계산료 여유는 기존 보수 충당액이며 공식 계산 API 단가가 아니다. 기존 추가 US$35 한도에서 일반 가용액 US$0.576241과 전용 미사용액 US$1.322513을 보존했다. 조건부 합계 US$1.898754를 이번 범위로 재배정하거나 예약하지 않았다. 모델 비용은 실제 입력량·최대 출력·현재 공식 단가와 필요한 여유를 결합해 별도로 확인해야 한다. 요청당 최대 출력은 8,192토큰으로 편성했으며 충분한지는 실제 실행 전 검토 대상이다.

## 문항별 판정과 보류 유지

원래 앱 요청 360개에 담긴 과제 전체와 문맥을 대조했다. 묶음 안에서도 각 항목은 자기 과제와 자기 출처를 갖는다. 작성자 판정·기대 교정문·유형·다른 채점자의 결과는 모델 본문에 넣지 않는다. 모델 응답은 익명 항목 ID로 원래 108개 슬롯에 되돌린다. 개별 요청에 대응하는 과거 응답을 새 묶음 응답으로 재분류하지 않는다.

- 문항·모델 중복, 누락, 교체 전 ID, 과제·출처 불일치를 요청 준비 단계에서 거절한다.
- 응답 누락·잘림·항목 ID 중복·항목 누락이면 해당 묶음의 36개 슬롯을 미측정으로 남긴다.
- 존재하지 않는 원문 구간의 교정이나 다른 문항의 출처를 인용하면 해당 문항의 판정을 보류한다.
- 두 AI의 불일치와 출처 부족을 다수결로 덮지 않는다. 108개 고정 분모를 유지한다.

이 방식은 공통 문맥의 영향으로 개별 요청과 다른 판정을 낼 수 있다. 입력을 정확히 보존한 검사만으로 의미적 동등성·영어 정확성·참조 검토자 자격을 입증하지 않는다. 기존 7차원 참조 역할 통제, 노출·가족 검토, 작성 기준 이견은 남아 있다. **정식 참조 0/60, 실제 예비평가 생성 0/360·채점 0/1,440, 확인 평가·학습 대리 지표·운영·출시 관문은 계속 보류**다. 이번 묶음 초안이 전체 개선 목표를 대체하지 않는다.

## 검증과 다음 실행 조건

새 도구와 검사는 Node 22.22.2·24.22.1에서 각각 8/8 통과했고 ESLint는 exit 0이다. 합성 응답의 54개 일치는 응답 분해 검사에만 사용했으며 영어 점수로 등록하지 않았다. 실행한 명령:

```powershell
node --test .taskmaster/scripts/test-ai-quality-v147-blind-reference-groups-v1.mjs
node node_modules/eslint/bin/eslint.js .taskmaster/scripts/ai-quality-v147-blind-reference-groups-v1.mjs .taskmaster/scripts/test-ai-quality-v147-blind-reference-groups-v1.mjs
```

관리 원본의 phase161 `prepare.mjs`로 원본 지문과 본문을 대조해 3개 요청을 생성했다(exit 0). 제품 코드·실행 설정을 바꾸지 않아 제품 단위·타입·빌드는 재실행하지 않았다. Task Master T24·T24.2·T24.3은 `in-progress`로 갱신한다. 기존 T25 검토 상태와 과거 72/72·71/72 근거는 유지한다. 대시보드·원장·이력 보존의 최종 결과는 phase161 `closeout-verification.json`을 따른다.

실행 전 체크리스트:

1. 묶음 응답의 출력량·문맥 간섭과 참조 역할 통제를 검토한다.

3. 정확한 새 호출 범위와 기존 한도 내 재배정에 대한 승인을 받는다.
