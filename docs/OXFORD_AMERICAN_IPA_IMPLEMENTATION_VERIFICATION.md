## 실행 중 발견과 조치

- 이미지 뒷면 IPA DOM 검사에서 0개/기대 1개인 RED를 확인한 후 텍스트 전용 `WordIpa`를 연결했다. 마지막 두 엔진 검사에서는 통과했다.
- JSON 배열 추론이 tuple 타입과 맞지 않아 타입 검사가 실패했다. 생성기의 2칸 배열 검증을 전제로 형식을 명시한 뒤 타입 검사를 통과했다.
- 편집 QA가 읽기 전용인 기존 뜻을 직접 입력하려다 실패했다. ‘다른 뜻 추가’ 경로와 정상 백업의 `activeSessionId: null`을 사용하는 fixture로 고쳤다. 앱의 뜻 보호 규칙을 완화하지 않았다.
- QA가 재개 버튼의 정상 저장을 IPA 표시 쓰기로 집계했다. 재개 저장 완료 후 읽기 전용 구간을 대조하도록 수정했다.
- 초점 복귀를 고정 두 프레임 후 확인한 검사가 한 번 실패했다. 창 닫기와 방문 기록 전환의 실제 초점 결과를 최대 2초 기다린 뒤 같은 요소임을 확인한다. 앱 초점 코드는 변경하지 않았다.
- 위치 QA의 전체 이미지 경로 누락은 기존 로컬 자산 경로 지정으로 해결했다. Worker가 빌드 파일을 잡고 있던 이전 EBUSY 빌드는 소유 서버 종료 후 다시 빌드해 해결했다.
- 기존 보호 동작에 추가한 누락/중복 데이터 검사와 화면 확대 검사는 회귀 보강이다. 이미 통과하는 검사를 새 기능의 RED 단계로 계산하지 않는다.
- 이번 재검토 중 WebKit의 기기 음성 QA에서 학습 뜻을 바꾼 뒤 사전 안내 링크를 기다리다가 30초 시간 초과가 한 번 발생했다. 앱 오류 로그는 없었으며 입력값·IPA·초점 태그·대화상자 수를 남기는 실패 진단을 추가했다. WebKit 재실행 두 번은 모두 통과했다. 해당 단발 실패의 원인은 미확정이며, 기존 startup·401 원인과 같은 문제라고 단정하거나 해결됐다고 표시하지 않는다. 첫 실패 로그는 `work/ipa-plan-review-20261019/device-speech-webkit-first-timeout.log`다.
