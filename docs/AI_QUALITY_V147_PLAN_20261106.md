## 평가와 판정

1. T33으로 앱 원인과 모델 가설을 나눈다. 앱 후처리는 같은 원응답의 정책 교체/제거 비교로 확인한다. 프롬프트·모델 변경 효과는 승인된 실제 matched 비교 없이는 입증되지 않는다.
2. 기존60문장(단어30/문법30, 정상20/교정25/보류15)은 **예비 진단 전용**이다. 기존57/60 및층별 수치는 예비 진단 표시로만 보존하며 출시 자격이 아니다. 12개 judge 보정도 독립 영어 검토를 대체하지 못한다.
3. T34에서 대상 수준/수업/오류군과 피해별 허용 위험을 정의하고 사용자 승인을 받는다. N·층 배분·반복 r·정밀도/효과·신뢰수준·군집·다중검정/중간확인·중단 기준을 결과 보기 전에 결정한다. **현재 N/r·위험한계는 미결정이며 따라서 출시는 held다.** 근거 없이300개 같은 새 숫자로 대체하지 않는다.
4. 예를 들어 독립적이고 대표적인 Bernoulli 표본이라는 가정에서60회0오류여도 단측95% 오류율 상한은 `1−0.05^(1/60) ≈ 4.87%`다. 현재의 의도적 층화·유사문장·반복은 그 가정을 자동 충족하지 않는다. 이는 실제 서비스 오류율 추정이 아니라 작은 표본의 한계를 보여 주는 설명이다.
5. 예비 결과 후 수정한 소스를 다시 동결하고 독립 작성/검토자가 새 오류 가족·허용 gold를 봉인한다(T35). 유출/결과 열람/후보 변경 시 해당 자료를 개발용으로 전환하고 새 프로토콜/미공개 자료/필요한 새 승인을 마련한다. 확인 평가의 실패를 같은 자료로 반복해 통과시키지 않는다.
6. T36은 전량/원분모/미측정·실패 비용을 보존하고 모델/유형·가족·반복별 결과와 위험 상한/짝 비교를 보고한다. 중대 오류0·필수 정상 오거절0·미측정0은 필수 관측 조건이며 무위험 보증이 아니다. 사전 승인한 위험·개선/비열등·변동성 한계까지 충족해야 한다.
7. T37은 정확성 검토와 자기 설명→힌트 없는 새문장 적용→사전 정한 지연 재확인을 구별한다. 참가/검토자 미확보는 held다. 만족도나 문구 선호만으로 이해 성공을 세지 않는다. 장기 학습 효과는 별도 충분한 연구 없이는 주장하지 않는다.
8. T40은 위 근거가 모두 있을 때만 `preproduction-eligible`. 게시/전용 운영QA 승인→T38 실제경로→T31 공개/환경→T39 기간점검→T32가 끝나야 `operational-verified`다. 알려지지 않은 미래 오류까지 해결됐다고 표현하지 않는다.
