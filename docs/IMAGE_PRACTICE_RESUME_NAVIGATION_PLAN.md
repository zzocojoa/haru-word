# 이미지 연습 위치 저장·카드 이동 개선 계획

## 1. 목표와 확정 사항

현재는 연습 화면이 열릴 때마다 카드 번호를 0으로 초기화하여 위치가 사라진다. 마지막 카드의 고유 ID를 계정별로 저장하도록 개선한다.

- 같은 계정으로 휴대폰·PC에서 이어 보기
- 이전·다음·카드 번호로 이동
- 재개하거나 다른 카드로 이동하면 그림 앞면부터 표시
- 여러 기기의 저장이 충돌하면 덮어쓰기 전에 선택
- 위치만 저장하며 성적·확인 이력·학습 완료 수는 추가하지 않음

## 2. 화면과 이동 방식

연습창 하단에 작은 이동 바를 고정한다.

```text
           위치 저장됨
[ 이전 ]   [ 52 / 3,809 ▾ ]   [ 다음 ]
```

- 앞면·뒷면 모두에서 이동할 수 있고, 이미지 로딩·실패 중에도 이동을 허용한다.
- 번호를 누르면 숫자 입력창을 열어 원하는 카드로 이동한다. 단어 목록은 노출하지 않는다.
- 첫 카드에서는 이전, 마지막 카드에서는 다음을 비활성화한다. 처음으로 돌아가려면 번호 1로 이동한다.
- 뒷면의 중복된 ‘다음’ 버튼과 오류 화면의 ‘건너뛰기’ 버튼은 이동 바로 통합한다.
- 카드 이동 시 정답·발음 펼침·이미지 오류 상태를 초기화한다.
- 브라우저 뒤로 가기와 연습창 닫기의 기존 동작은 유지한다.
- 저장 상태는 연습창 안에서 ‘위치 저장 중’·‘위치 저장됨’·‘저장 실패 · 다시 저장’으로 짧게 표시한다.

## 3. 계정별 저장 구조와 호환성

기존 학습 저장과 분리하여 위치 저장 때문에 성적 저장이 충돌하지 않도록 한다.

- D1에 계정당 한 행을 저장하는 image_practice_positions 테이블을 추가한다. 필드는 사용자 ID·카드 항목 ID·독립 revision·수정 시각이다.
- /api/image-practice/position을 추가한다.
  - GET: 저장 위치와 revision 조회. 최초 사용자는 빈 위치를 반환하며 조회만으로 DB를 수정하지 않는다.
  - PUT: 카드 항목 ID와 예상 revision을 받아 원자적으로 저장한다. 충돌은 409로 반환한다.
- 사용자 식별은 기존 서버 인증을 사용한다. 인증·요청 출처·본문 크기·유효한 이미지 항목 ID를 검증한다.
- 기존 /api/state, 학습 revision, 성적, 복습 일정과 백업 형식은 변경하지 않는다. 이미지 연습 위치는 기존 학습 백업의 포함 대상에서 제외한다.
- 위치 조회는 연습창을 열 때 실행한다. 홈 초기 구동에 추가 요청이나 이미지 자료 다운로드를 발생시키지 않는다.
- 카드 순서와 뜻별 이미지 제외 규칙을 유지한다. 저장한 카드가 제외되었다면 원래 순서의 다음 유효 카드로, 없으면 첫 카드로 이동해 안내한다. 원래 목록에서도 사라진 ID는 첫 유효 카드로 처리한다. 조회만으로 기존 저장 위치를 덮지 않는다.

## 4. 저장 실패·빠른 이동·동시 사용

- 화면 이동은 즉시 반영한다. 서버 저장은 한 요청씩 처리하고, 빠르게 여러 번 이동하면 대기 위치를 마지막 카드 하나로 합친다.
- 저장 컨트롤러는 연습창 바깥에 두어 창을 닫아도 진행 중인 저장을 마친다. 이전 카드의 늦은 응답이 최신 위치를 ‘저장됨’으로 표시하지 않도록 구분한다.
- 미저장 위치와 기준 revision은 계정별 브라우저 캐시에 보관한다. 다른 계정의 위치를 표시하거나 전송하지 않는다.
- 최초 조회에 실패하면 캐시가 있을 때 해당 위치를 보여 주고, 없으면 재조회 화면을 표시한다. 서버 위치를 모르는 상태에서 첫 카드로 덮어쓰지 않는다.
- 저장 실패·응답 시간 초과 시 이동은 유지한다. ‘다시 저장’에서는 서버 위치를 먼저 확인하며, 실패한 쓰기를 무조건 반복하지 않는다.
- 충돌 시 ‘다른 기기 위치로 이동’과 ‘현재 위치 저장’을 제공한다. 현재 위치 저장도 최신 revision으로 검사하며 강제 덮어쓰기는 하지 않는다.
- 다른 기기에서는 서버 저장이 확인된 위치까지 이어 볼 수 있다. 종료 순간의 네트워크 실패는 원래 기기의 캐시로 복구한다.
- 브라우저 저장소를 사용할 수 없으면 메모리에서 위치를 유지하고 기기 내 복구 제한을 알린다. 로그아웃·인증 실패·계정 변경 시 이전 계정의 대기 요청과 늦은 응답이 새 계정 상태에 섞이지 않도록 한다.

## 5. 구현·검증·출시 순서

1. 최신 main에서 codex/image-practice-resume-navigation 브랜치를 만들고, 별도 저장 API·추가형 DB 마이그레이션을 구현한다.
2. 위치 저장 컨트롤러와 이동 바를 연결하고 기존 ‘닫으면 첫 카드로 초기화’ 문서·검사를 수정한다.
3. 다음 회귀 검사를 수행한다.
   - 닫기·탭 이동·새로고침·다른 브라우저에서 같은 위치로 재개
   - 앞뒷면 이동, 번호 입력 오류, 처음·마지막 카드, 제외된 카드와 빈 목록
   - 빠른 연속 이동, 늦은 응답, 저장 실패·시간 초과·재시도, 두 기기 충돌
   - 계정 격리와 기존 학습 문서·revision·백업 불변 확인
   - 이미지 선로딩은 기존처럼 다음 카드 한 장으로 제한
4. 로컬 가상 계정으로 Chromium·WebKit, 320/390/1440px, 글자 200%, 키보드·axe 검사를 수행한다. 기록 0·365·1,825회차와 느린 네트워크에서 기존 초기 구동 성능도 비교한다.
5. 전체 테스트·타입·린트·빌드와 로컬 Node 22/24 검사를 수행한다. GitHub CI 차단이 지속되면 로컬 결과와 구분해 기록한다.
