# 테스트 코드의 예문 노출 점검 · 2026-11-07

기존 목록에 포함하지 않았던 **테스트 프로그램123개**를 실행하지 않고 TypeScript5.9.3 구문 분석기로 읽었다. 정적 문자열12,596개와 보간 템플릿163개를 방문했다. 아래 필터에 맞는 문자열629회·서로 다른 문장 형태433종을 찾았으며,그중399종은 기존426개 선택 원문 목록에 없다. 동적 문장 틀15개는 식별만 했고 실제 생성 결과를 펼치지 않았다.

**399개가 모두 빠진 실제 입력 문장이라는 뜻은 아니다.** 입력·교정안·테스트 설명·기타 문장이 섞인 검토 전 후보이다. 이 자료는 로컬 점검용이며 모델 요청에 보내지 않는다. 실제 원문 역할·문맥/대상·가족 관계를 확인하지 않은 채 기존 fresh 정책이나 gold에 합치지 않는다. 과거 테스트 실패·품질 점수·문법 정답 라벨을 바꾸지 않았다.

## 재현 범위와 규칙

선정 파일은 phase36/source-coverage-audit.json의 programFilesNotExtracted123개로 고정하고 각각의 원본 지문을 확인했다. tests/ 바로 아래 지정 .test.mjs만 읽으며 링크/다른 경로·원본 변경은 중단한다. .env·실행 설정·운영 학습 기록·출력/백업을 검색하지 않는다. 소스 import나 보간식을 실행하지 않고 문법 트리만 읽는다. 현재 새 도구 자체의 예문,다른 .taskmaster 스크립트와 과거 보관 평가까지 전체 검사한 것으로 세지 않는다.

정적 후보 필터: StringLiteral/보간 없는 backtick 문자열 중 정상 Unicode·2,000자 이하·줄바꿈 없음·영어 단어 형태2개 이상·마지막 문장부호(.!? 또는 뒤의 따옴표)가 있는 값. URL 시작과 키 형태/민감 이름 문맥은 제외한다. 이는 언어 판별기나 원문 입력 판별기가 아니다. 한 단어 명령·선택지 조각·여러 줄/2,000자 초과·다른 동적 생성은 이 후보 목록으로 다뤘다고 하지 않는다. 방문 전체 분모와 필터 제외 건수도 남겼다.

예를 들어 tests/ai-quality-semantic-roles.test.mjs의 `Who helped her?`는 소스 위치가 있는 정적 후보다. tests/ai-quality-morphology.test.mjs의 `They performed the task ${adjective}.`는 미전개 틀이다. 형용사 목록을 실제로 순회해 모든 문장을 모았다는 뜻이 아니다. 정규식/주석의 예문은 문자열 리터럴로 세지 않는다. 원본 지문·UTF-16 시작/끝·행/열·원본 구간 지문·부모 구문 종류를 남겨 해당 후보를 재확인할 수 있다. 동일 표면의 모든 출처 ID를 유지한다.

## 점검 도구의 판정 한계

`matchProgramExposureAuditV1`은 일치 시 seen-program-text-candidate를 돌려준다. 일치하지 않아도 unresolved-not-a-freshness-clearance이며 통과증을 주지 않는다. 입력 역할·구조 가족·프로젝트 전체 노출·실제 영어 정확도·학습 효과를 true로 내보내지 않는다. 라벨/교정안/설명 후보가 들어 있을 수 있는 이 로컬 목록을 모델용 노출 근거로 투영하는 기능은 없다. 기존1472출처/426표면의 global corpus·본문/바이트 한도·실행기/모델 요청도 그대로다.

다음 점검 체크리스트:

1. 후보의 실제 호출 위치에서 원문/교정안/설명/기타 역할과 문맥·대상을 확인한다.
2. 동적 틀15개와 별도 생성기/배열 조합의 유한 생성 범위를 근거와 함께 펼친다. 미전개를 완전 추출로 세지 않는다.
3. 원문으로 확인한 자료만 별도 정책 버전/출처로 연결하고 기존426기록과 원점수를 보존한다. 고정 본문이 바뀌면 새 binding을 검토한다.
4. 문장 표면이 달라도 같은 구조 가족인지 별도 확인한다. 검사하지 않은 교재 영한 혼합/선택지 조각/다른 보관 평가와 새 도구 자료를 남은 범위로 유지한다.
