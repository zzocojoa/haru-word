# T34.3 실제 학습 화면의 문맥 보완·재요청·재조회 검증

2026-11-08 · `ai-quality-v147` / `codex/ai-quality-v147` · 로컬 합성 계정 전용.

## 결과와 검증 범위

**단어·문법 화면에서 요청 버튼 → 추가 질문 표시 → 문맥/표현 형식 변경 → 명시적 재요청 → 클라이언트 저장 → 페이지 재방문·재조회가 연결됨을 확인했다.** phase61의 컴포넌트 전용 표시 검사와 달리, 기존 전체 빌드의 실제 학습 화면과 클라이언트 요청/저장 코드를 사용한다. 응답은 전부 고정 합성이며 실제 모델의 영어 판단을 확인한 결과가 아니다.

Node22.23.4/24.22.1 **각각** Chromium·WebKit×Sol/Terra/Astra 설정×단어/문법의 **12개 흐름**, 가상 제공자 응답 **24개**가 exit0이다. 새 검사 파일의 ESLint도 exit0이다. 모델 이름은 요청·저장 경로의 설정이며 세 모델을 실제 호출하거나 능력을 비교한 것이 아니다.

## 관측 가능한 통과 조건

| 단계 | 실제 확인 |
| --- | --- |
| 첫 요청 | 전체 빌드 화면에서 요청 버튼을 누르면 가상 제공자 응답1개만 발생하고, 원래 문장과 시점 질문이 표시됨 |
| 문맥 보완 | 학습자가 문장 상황을 적고 표현 형식을 `reply`로 선택함. 편집 자체로 제공자 호출이 발생하지 않음 |
| 두 번째 요청 | 새 버튼 클릭은 새 UUID·새 문맥 지문을 사용함. 실제 제공자 요청 본문에 문맥과 `reply`가 포함됨 |
| 결과 보관 | 첫/둘째 UUID의 영수증을 각각 조회할 수 있음. 두 번째 피드백 전체가 클라이언트 저장 후 학습 상태 GET과 같음 |
| 재방문 | 페이지를 다시 불러와 해당 학습 화면에 진입하면 두 번째 결과·문맥·표현 형식이 유지됨. 새 제공자 호출0 |
| 데이터 보존 | 원래 문장·첫 답·독립 성적·친숙도, 문법 답·관찰·진도·복습 일정/기록 등 명시한 필드가 같음. 제안 교정을 자동 적용하지 않음 |

이 검사는 시점 질문을 사용하는 고정 합성 예시1개를 여러 경로에서 반복한다. 12개 독립 영어 문항이나 질문 전체의 적절성 표본으로 세지 않는다. 다른 질문 종류의 전달 근거는 [phase61 보고서](AI_QUALITY_V147_VISIBLE_QUESTION_20261108.md)를 따른다. 두 화면의 실제 스크린샷도 확인했지만 모든 화면의 시각·접근성·보조 기술 검증을 완료했다는 뜻은 아니다.

## 재현과 원본

SOURCE에서 설치된 Node/Playwright를 사용하고 새 출력 폴더를 지정한다. 기존 출력은 덮어쓰지 않는다.

```powershell
$env:QA_OUTPUT_DIR = 'C:\Users\user\Documents\ChatGPT\하루단어\outputs\question-ui-new-run'
$env:QA_PLAYWRIGHT_PATH = 'C:\Users\user\.agents\skills\gstack\node_modules\playwright'
node .taskmaster/scripts/test-ai-quality-v147-question-ui-v1.mjs
```

권위 있는 결과는 ROOT `outputs/ai-quality-v147-implementation-20261106/phase62/` 아래 `ui-node24-verified/results.json`, `ui-node22-verified/results.json`, `ui-rows.json`, 제공자 요청/응답 원문, 단계별 스크린샷과 실제 명령·종료 코드다. 준비 기록은 `.taskmaster/docs/ai-quality-v147-question-ui-preparation-v1.json`이다. Worker·브라우저는 종료하고 성공·실패 실행의 합성 D1/R2 파일은 보존한다.

최초 Node24 실행2건의 실패도 보존했다. 첫 검사는 피드백 자체에 없는 `requestId`로 저장 완료를 기다렸다. 현재 스키마를 확인해 피드백 전체의 엄격한 동등성을 비교하고, UUID는 별도 영수증 조회로 확인하도록 수정했다. 둘째는 중첩 label의 정확 일치 선택자가 select를 찾지 못했다. 기존 제품 QA와 같은 정확한 접근 가능 이름의 `combobox` 역할로 선택했다. 제품 코드를 바꾸거나 저장·UUID·문맥 검사를 제거해 통과시키지 않았다.

## 남은 조건과 운영 영향

이번 범위에서 질문 표시·문맥 보완·재요청·재방문 경로가 확인됐지만, 모든 학습 화면·실패 경로·iPhone/VoiceOver·운영 인증을 검증한 것은 아니다. T37의 AI 설명 정확성/새 예문 적용성과 실제 사람 학습 효과 한계, T38의 승인된 운영 합성 계정 확인은 남아 있다. 실제 영어 품질·참조/채점기 자격·위험/독립 표본/반복·최종 입력과 견적·확인/일반화·출시/1일/7일도 미완료다. T34/34.3의 `review`와 전체40개/세부133개 범위를 유지한다.
