# T34.3 · 평가 입력 형식과 별도 제품 정책 검사 연결 — 2026-11-08

평가 요청이 실제 생성 요청의 목표·형식을 생략하지 않도록 새 선택 프로필을 주 평가의 요청 생성→입력 계산→캡처→보고·읽기전용 복구에 연결했다. **실제 생성 요청과 평가 대상의 전체 목표 필드가 다르면 전송 전에 차단**하며, AI 영어5차원/중대4위험/근거3축과 **기계적 제품 정책 검사**를 별도로 보존한다. 이 작업은 평가 도구 개선이며 새 영어 품질 합격이 아니다. 추가 실제 API/키/비용0, 기존83/84와 자격 보류를 유지한다.

## 달라진 동작

- 생략된 contextKind는 sentence로 명시한다. 실제 요청에 명시된reply/title/command와 생략된 기본값을 구분한다. contextNote의 문구는 형식 선택으로 사용하지 않는다.
- 단어 요청의word/pos/meaning/expression, 문법 요청의target/targetCriterion/role/pattern/task/check/stem과 문장·문맥을 평가 입력에 전달한다. 표시용target 문자열만으로 실제 선택된 뜻/품사를 추정하지 않는다.
- 평가 입력의requestInput 해시는 캡처한 원래 생성 요청 본문과 대조한다. 생성 단계도 동결된 사례의 실제 입력과 대조하므로, 재봉인한 잘못된 목표 본문도 그 요청의계산/모델 전송 전에 보류한다.
- 제품의 제한된 관측 규칙은 별도policyCompliance로 남긴다. 검토된 불완전 명사 조각의 두 판정 보류·교정문 비움·질문 노출, natural 원문 유지, uncertain 교정 비움, needs_work의 실제 다른 교정문을 확인한다. **전체 제품 정책이나 영어 의미를 모두 증명하는 검사는 아니다.**
- 네 영어 판정이 모두pass여도 이 별도 검사에 실패하면 held-policy다. 반대로 기계적 검사pass가 영어pass를 뜻하지 않는다. 가상의 나쁜 피드백인 보정 문항은 의도적으로 정책fail일 수 있으며, 학습자에게 실제 표시된 성공으로 세지 않는다.
- 근거가 부족하거나 충돌하면 영어 점수와 별도로 held-reference, 네 검토의 문맥/보류 필요성 판단이 다르면 held-disagreement로 남긴다. 보정 문항의 3축도 기대값과 모두 일치해야 하며, 실패하면 주 평가 생성을 시작하지 않는다.
- 새 프로필은 제품 영어 기준2와분리3축·문맥 버전 해시를 모든 주 평가/보정 요청에 사용한다. 기존 프로필은 선택하지 않으면 그대로 작동한다. 자격 차단은 유지하고 새 프로필을 자동 라이브 실행하지 않는다.
