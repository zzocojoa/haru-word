## 왜 일반 문법 교정 채팅과 다르게 보이는가

하루단어는 문법 교정 외에 단어/수업 목표·뜻·과제 달성, 원문 문법, 교정, 이유를 함께 요구한다. 운영 v142는 숨긴 구조 분석도 요구한다. 후보는 구조 생성을 제거했지만 목표 판정과 문법의 경계, 부족한 문맥에서 보류할 조건을 충분히 맞추지 못했다. 현재 API 입력은 문장과 필요한 목표 정보이며, 이전 ChatGPT 대화 전체를 전송하지 않는다.

확인된 설계 원인은 다음과 같다.

1. **모델이 uncertain을 반환해야 문맥 질문을 요구한다.** 모델이 잘못 확신하면 입력 자체의 문맥 부족을 독립적으로 차단하지 못한다.
2. **교정 보호는 제한된 모순 검사다.** 부정·수량·일부 시간·참여자 변화는 확인하지만 낱말을 명령문으로 만든 의도 변화는 잡지 못한다. 저장된 가시 이유로 wire를 재구성한 실패 사례3개가 현재 계약·교정 검사를 통과함을 오프라인 재현했다.
3. **평가 라벨의 경계도 모호하다.** 격·조동사 수일치·to부정사 누락 사례에서 교정은 정확해도 목표 needs_work가 고정 허용값 appropriate와 달라 실패한다. 이를 모두 영어 교정 오류라고 부르면 잘못된 설명이다. 결과를 본 뒤 현재 허용값이나 점수를 유리하게 바꾸지 않았다.

프롬프트 변경 문장 하나의 인과 효과나 모델 내부 판단 이유는 입증하지 않았다. 일반 ChatGPT 채팅과 같은 모델·문장·지시·문맥·출력 조건을 맞춘 대조 검사도 하지 않았다. 따라서 모델 이름이나 API 자체만을 원인으로 단정하지 않는다. 구조화 출력도 내용 오류를 포함할 수 있다는 [OpenAI 공식 설명](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)과 일치하는 관측이다.
