## 사용과 복구

오늘의 학습 → 이미지 연습에서 그림을 확인하고 아래 **이전 / 카드 번호 / 다음**으로 이동한다. 번호를 누르면 1부터 전체 카드 수 사이의 정수로 이동할 수 있다. 처음과 끝에서 순환하지 않는다. 이미지가 로딩 중이거나 실패해도 이동할 수 있고, 카드 이동·다시 열기는 항상 그림 앞면이다. 카드별 확인 이력·성적·완료 수는 기록하지 않는다.

번호 입력으로 이동한 뒤에는 카드 번호 버튼에서 키보드 탐색을 이어간다. 이전·다음 이동은 버튼 초점을 유지하고 현재 카드 번호를 별도 live region으로 알린다. 이동 버튼의 키보드 초점 외곽선은 스크롤 영역 안에 표시한다.

이동한 카드의 고유 ID를 계정별로 저장한다. ‘위치 저장됨’이 표시된 위치는 같은 계정의 다른 브라우저에서 이어 볼 수 있다. 연습창을 닫거나 다른 탭으로 가도 진행 중인 저장은 계속된다. 브라우저 자체를 종료하는 순간의 저장 성공은 보장하지 않으며, 해당 기기의 계정별 캐시로 미저장 위치를 복구한다. 위치는 기존 학습 백업에 들어가지 않는다.

같은 브라우저에서 여러 탭을 쓰면 마지막으로 직접 이동하거나 원격 위치를 선택한 결과가 기기 내 복구 기준이다. 다른 탭의 조회나 이전 저장의 늦은 성공·실패 응답이 최신 미저장/저장 완료 캐시를 덮지 않도록 보호한다. 원격 위치 선택은 선택 전에 남은 다른 탭 초안을 교체하되, 선택 조회를 기다리는 중 발생한 더 최신 이동은 보존한다. 오래된 실패가 새 저장을 다시 미저장 상태로 되돌리지 않는다. 새로고침 후에도 서버 위치부터 확인하며 다른 기기의 변경은 선택 없이 덮지 않는다.

예: 한 탭이 원격 위치를 조회하는 동안 다른 탭에서 C→B→C로 이동해도 마지막 C는 새 이동이다. C가 아직 미저장이라면 앞선 원격 조회가 이를 지우지 않으며, 새로고침 뒤 서버와 다르면 C에서 충돌 선택을 기다린다.

| 표시/상황 | 복구 방법 |
|---|---|
| 위치 저장 실패 | 현재 화면에서 계속 이동할 수 있다. **다시 저장**은 서버 위치를 먼저 읽고 기준 revision이 같을 때만 다시 저장한다. 직전 쓰기의 ID·revision+1이 일치하고 현재 최종 위치도 같으면 추가 쓰기 없이 완료한다. 추가 이동이 대기 중이면 어느 기기의 저장인지 구분할 수 없어 선택을 요구한다. |
| 처음 위치를 읽지 못함 | 캐시가 있으면 그 위치를 보여 주되 쓰기를 보류한다. 없으면 **다시 불러오기**를 제공한다. 확인되지 않은 첫 카드로 덮어쓰지 않는다. |
| 다른 기기에서 위치 변경 | **다른 기기 위치로 이동**은 최신 서버 위치를 읽는다. **현재 위치 저장**은 화면에 표시된 카드(제외 카드의 대체 카드 포함)를 선택하고 서버를 다시 읽어 확인한 revision으로 저장한다. 그 사이 다른 기기에서 또 바뀌면 다시 선택하며, 같은 화면에서 추가 이동했다면 마지막 위치를 유지한다. |
| 저장 카드가 뜻/품사 필터에서 제외됨 | 원래 순서의 다음 유효 카드, 없으면 첫 유효 카드로 안내한다. 원래 목록에도 없는 ID는 첫 유효 카드로 처리한다. 조회·안내만으로 위치를 저장하지 않는다. |
| 기기 내 복구 불가 안내 | 브라우저 저장소가 차단되거나 손상된 경우 메모리와 서버 저장을 사용한다. 창을 나가기 전에 서버 저장을 확인한다. |
| 로그인 확인 안내 | 새로 로그인한 뒤 페이지를 다시 연다. 이전 계정의 대기 쓰기는 새 계정으로 전송하지 않는다. |

예: PC에서 52번으로 이동 → ‘위치 저장됨’ 확인 → 휴대폰에서 같은 계정으로 연습을 열면 52번의 앞면이 나온다. 뜻을 바꿔 52번이 제외됐다면 다음 유효 카드를 보여 주고 안내한다. 화면의 번호는 현재 필터 기준이므로 저장 값은 번호가 아닌 `entryId`다.

## 저장 계약

- `image_practice_positions`: `user_id` 기본키, `entry_id`, 독립 `revision`, `updated_at`. 학습 테이블과 외래키를 맺지 않는다.
- `GET /api/image-practice/position`: 인증된 계정의 위치. 없으면 `{ "entryId": null, "revision": 0, "updatedAt": null }`. 읽기만 수행하며 모든 응답은 `no-store`다.
- `PUT /api/image-practice/position`: `{ "entryId": "유효 이미지 항목 ID", "revision": 0 }`. 첫 저장은 충돌 시 삽입하지 않는 단일 SQL, 이후 저장은 예상 revision 조건의 단일 UPDATE/RETURNING이다. 성공 시 전체 위치, 충돌 시 409다.
- 기존 서버 인증·동일 출처 검사·JSON 검증·실제 스트림 1,024바이트 제한을 사용한다. 항목 ID는 승인된 이미지 목록으로 검증한다. 클라이언트의 `x-image-practice-owner`와 현재 서버 계정이 다르면 401로 차단한다. 헤더는 인증 수단이 아니며 서버 인증이 우선한다.
- 클라이언트는 한 요청과 최신 대기 위치 한 개만 유지한다. 저장 중 캐시에는 전송한 ID와 기준 revision도 남긴다. ID·revision 일치만으로 작성자를 판별하지 않으므로 응답 유실 후 추가 이동이 대기 중이면 명시적 선택이 필요하다. 확인된 충돌은 캐시에도 남겨 새로고침 뒤에도 선택을 요구한다. 409 뒤 조회가 오래된 revision을 반환하더라도 자동 쓰기 루프로 돌아가지 않는다. 쓰기를 자동 재시도하지 않는다. 시간 제한은 조회 20초·저장 25초다.
- 컨트롤러는 `LearningScreens` 수명을 따르고, 계정 변경·언마운트 때 취소한다. 이전 요청의 응답과 정리는 새 요청/계정에 적용하지 않는다. 캐시 키는 `haru-image-position-v1:<인코딩한 계정 ID>`다. 개인 문장·답안은 포함하지 않는다.
- 캐시 version 1의 선택적 `navigationId`는 직접 이동마다 새 UUID로 바뀌고 조회·저장·실패 응답에서는 유지된다. 같은 카드로 돌아온 새 이동을 이전 캐시와 구분하기 위한 로컬 식별자이며 API·백업·진단에 보내지 않는다. 식별자 없는 기존 캐시도 읽는다. 이 보호는 수정된 코드를 실행하는 탭 사이에 적용되며, 계속 열린 구버전 탭과의 혼합 실행이나 여러 프로세스의 localStorage 원자성을 보장하지 않는다.
- 홈 최초 구동에는 위치 GET, 이미지 인덱스, 이미지 요청을 추가하지 않는다. 연습 진입 때 조회하고 그림은 현재 카드와 다음 한 장만 요청한다. 카드 이동은 브라우저/앱 방문 기록에 추가하지 않는다.
- `/api/state`, 학습 revision, 성적·복습 일정, 기존 백업/복원 스키마와 AI 실행 정책은 그대로다. 위치 요청의 계정·ID·이동 이력을 앱 진단에 추가하지 않는다.

## 마이그레이션과 롤백

현재 v137의 버튼 간격 회귀는 **v136** 앱으로 복구하며 위치 테이블·새 데이터를 보존한다. [현재 복구 순서](../OPERATIONS.md#이미지-연습-버튼-간격-v137--2026-10-18)를 따른다. 아래 v135→v134는 위치 저장 기능 출시 당시의 역사적 복구 기준이며 이번 CSS 변경에 적용하지 않는다.

`npm run db:generate`로 생성한 `drizzle/0005_flippant_enchantress.sql`은 새 테이블 한 개만 만든다. 이전 SQL·snapshot·journal 항목은 보존하고 새 snapshot/journal 항목만 추가했다. 로컬 검증용 Worker는 별도 `work/image-practice-resume/*-local-d1-*`의 새 가상 DB를 사용하며 기존 `.wrangler/state`나 운영 DB를 QA 대상으로 사용하지 않는다.

사용자가 승인한 v135 게시에서는 기존 Sites 절차가 운영 마이그레이션을 적용했다. 새 위치 테이블과 4개 열·기존 8개 테이블 유지를 확인했고, 첫 연습 조회 전후 0행으로 GET 무쓰기를 확인했다. SQL을 수동 재실행하지 않았다. Site ID·DB/R2 바인딩·환경 revision 71·공개 범위·결제 설정은 유지했다. 위험도는 중간(계정별 비동기 저장과 충돌 경계)이다.

롤백 대상은 저장된 **v134** 앱 아카이브(`cf339eed5e824393156f45c2dc3adba7e83d41c0`)다. 새 위치 테이블과 데이터를 남기며 학습 기록·이미지 파일·백업을 복원하거나 위치 테이블을 DROP하지 않는다. v135 운영 확인에서 회귀가 없어 실제 롤백은 수행하지 않았다. 저장 버전 ID와 복구 순서는 [운영 안내](../OPERATIONS.md#이미지-연습-위치-저장-v135--2026-10-17)를 따른다.
