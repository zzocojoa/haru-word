# PDCA: 이미지 회상 연습 로직 개선 계획

**시범 승인 당시 계획:** 이 문서는 20개 로컬 시범의 범위와 절차를 보존한다. 후속 전체 이미지 연결·긴 단어 편집창 수정·병합/게시 결과는 [전체 UI 문서](OXFORD_WORD_IMAGES_FULL_UI.md)와 [최종 상태](releases/2026-10-16-oxford-images-release-status.json)를 따른다.

## 목표와 확정 범위

오늘 학습에 **이미지 → 영단어 회상 → 단어 확인** 방식의 별도 연습을 추가한다. 기존 친숙도 진단·뜻 회상 시험과 구분하고, 연습 결과는 저장하지 않는다.

- 사용자가 선택한 범위는 **오늘 학습의 별도 연습·성적 미기록·20개 로컬 시범**이다.
- 이미지 제작 브랜치 `228f8ba`의 `pilotEntryIds` 20개와 각 항목의 최신 승인 PNG를 사용한다. 실제 파일·해시와 현재 `main`의 교재 일치를 확인했다.
- 전체 호스팅·운영 게시·이미지 재생성·AI 채점은 이번 범위에서 제외한다.
- 현재 카드 자동화 작업은 보존하고, 최신 `github/main`에서 별도 작업 체크아웃과 `codex/word-image-pilot` 브랜치를 준비한다.

## PLAN — 구조와 동작 계약

**이미지 연결**
- 전체 제작 원장을 앱에 넣지 않고, 시범 20개의 ID·품사·기본 뜻·교재 지문·파일 해시·크기·로컬 주소만 추출한 작은 목록을 사용한다.
- 기존 단어 ID와 선택한 뜻으로 연결한다. 철자만으로 찾거나 다른 뜻을 추정하지 않는다.
- 개인 단어, 시범 목록 밖의 항목, 기본 뜻과 다른 선택 뜻에는 이미지를 표시하지 않는다.
- 준비 명령에서 현재 교재 지문과 원본 PNG 해시를 검증한다. 파일명은 이미지 해시를 사용해 주소에 정답 단어가 드러나지 않게 한다.

**연습과 기존 기록의 분리**
- 기존 `SheetDialog`와 화면 이동 구조를 재사용한다.
- 연습 상태는 화면 메모리의 **현재 위치·앞면/뒷면·이미지 로딩 상태**로만 관리한다.
- 닫기·다른 탭 이동·새로고침 후에는 처음부터 시작한다. 기존 수업을 시작하거나 진행시키지 않는다.
- `State`, `Session`, `Progress`, 저장 API, 백업 형식과 DB는 변경하지 않는다. 연습 컴포넌트에는 저장·채점 콜백을 전달하지 않는다.

**화면 계약**
- 오늘 학습 개요의 기본 학습 버튼 아래에 `이미지 연습` 진입 버튼을 둔다. 기존 진단·수업 화면에는 추가하지 않는다.
- 앞면 카드에는 이미지만 표시한다. 영단어·뜻·품사·발음·수준·예문은 공개 전 DOM과 접근성 표기에 넣지 않는다.
- 카드 아래 `단어 확인`을 누르면 뒷면에 영단어를 표시한다. 뜻·발음은 뒷면의 접힌 도움말에서 확인하며 예문은 기존 학습 화면을 사용한다.
- 뒷면의 `다음`으로 이동하면 새 카드의 앞면으로 초기화한다. 마지막 카드에서는 `처음부터`와 `닫기`를 제공한다.
- 로딩 중에는 단어 확인을 막고 닫기는 허용한다. 이미지 오류 시 안내와 `건너뛰기`를 제공하며 정답을 자동 공개하지 않는다.

## DO — 작은 단위의 TDD 구현

각 단계는 [PDCA Do 지침](C:/Users/user/.codex/skills/pdca-framework/references/do-prompts.md)을 먼저 읽고 **실패하는 행동 검사 하나 → 최소 구현 → 통과 → 필요한 정리** 순서로 진행한다. 컴파일 오류를 RED로 간주하지 않는다. 사전 광범위 리팩터링은 필요 없다.

1. **시범 자료 준비**  
   `npm run images:pilot:prepare` 명령을 추가한다. 승인된 20개와 교재 지문·PNG 해시를 먼저 검증한 뒤 로컬 공개 폴더에 복사한다. 같은 파일은 재사용하고 다른 내용의 기존 파일은 덮어쓰지 않는다. PNG는 Git에서 제외하며 이번 시범에서는 원본을 사용한다.

2. **이미지 선택 로직**  
   `resolveWordImage(word, selectedMeaning)`가 적합한 이미지 또는 미지원 결과를 반환하도록 구현한다. 첫 핵심 검사는 같은 철자의 은행·강둑 항목이 올바른 ID와 뜻으로만 연결되는 행동이다.

3. **앞면·뒷면 상태 전환**  
   이미지 확인 전 정답 비공개, 뒤집기, 다음 카드 초기화, 마지막 카드 종료를 구현한다. 이전 카드의 늦은 로딩 이벤트가 새 카드 상태를 바꾸지 못하게 한다.

4. **오늘 학습에 연결**  
   연습을 열 때 적합한 시범 항목만 고정된 시범 순서로 구성한다. 실제 개수로 진행 위치를 표시하고, 적합한 항목이 없으면 빈 상태를 제공한다. 현재 이미지와 다음 한 장만 요청한다.

5. **단어 편집창 미리보기**  
   같은 선택 로직으로 제목 옆에 작은 미리보기를 추가한다. 다른 뜻 선택·새 뜻 작성 시 즉시 다시 판단한다. 기존 편집 초안, 저장 실패 후 재시도와 닫기 보호는 유지한다.

6. **로컬 실행과 문서화**  
   내부 `imagePilotEnabled` 속성은 기본 `false`로 두고 개발 모드에서만 서버가 활성화한다. 운영 빌드에서는 진입 버튼·미리보기·이미지 요청이 발생하지 않아야 한다. 준비 명령과 로컬 확인 절차를 README에 기록하고 새 브라우저 검사를 기존 QA 목록에 등록한다.

## CHECK — 검증과 완료 기준

- **선택 검사:** 기본 뜻 일치, 다른 뜻·개인 단어·미지원 ID 차단, 교재 지문·파일 해시 불일치 시 준비 중단.
- **화면 검사:** 공개 전 정답 부재, 뒤집기·다음·종료·재시작, 느린 로딩·실패·늦은 응답, 닫기와 뒤로 가기.
- **기록 격리 검사:** 연습 전후 학습 상태·revision 동일, 연습에서 저장·AI 요청 0회, 기존 친숙도·최초 답·회상 성적·수업 시간 불변.
- **편집 회귀 검사:** 뜻 전환, 저장 오류 후 초안 유지·재시도, 미저장 편집 닫기 보호.
- **로컬 Chromium/WebKit:** 320·390·1440px, 글자 크기 200%, 키보드·포커스 복귀·axe, 정답을 포함하지 않는 장면 설명 검수. 실제 iPhone 검사는 별도로 표시한다.
- 최종 코드에서 `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`와 관련 브라우저 검사를 실행한다. 기존 경고와 새 실패를 구분한다.
- 완료 산출물은 검증된 시범 코드, 로컬 이미지 준비 명령, 화면 캡처와 검사 보고서다. CI가 계정 제한으로 실행되지 않으면 로컬 통과와 분리해 미검증으로 기록한다.
