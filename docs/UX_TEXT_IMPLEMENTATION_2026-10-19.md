## 발견한 문제와 검증 한계

- 초기 단위 검사 4건과 일부 브라우저 검사는 이전 문구를 기대해 실패했다. 해당 기대값/선택자를 갱신하고 기존 동작 검증을 유지한다.
- 작은 화면의 200% 글자에서 설정 label과 선택값이 좁게 눌리는 문제를 발견해 줄바꿈을 수정하고 회귀 조건을 추가했다.
- WebKit 시간 초과 검사에서 설정창 닫기 직후 오류 안내의 bounding box가 잠깐 화면 밖으로 측정됐다. 같은 실행에서 약 100ms 뒤 `y=129.39`, 높이 `138.78`로 안정되고 캡처에서도 안내가 보였다. 자동 스크롤을 테스트에서 실행하지 않고, 기존 ‘안내 전체가 844px 화면 안에 있어야 함’ 조건을 최대 5초 동안 기다리도록 바꿨다. 초안·백업·요청 수·revision 검증을 유지한 재실행은 통과했다. 이 검사 전환 문제를 과거 startup 원인으로 해석하지 않는다.
- 로컬 Worker가 빈 Wrangler 오류와 종료 코드 1로 두 번 종료돼 다음 친숙도 검사가 시간 초과됐다. 각 종료를 확인한 후 같은 빌드로 재시작했고 해당 검사는 통과했다. 두 번 모두 위치 회귀 검사 뒤 관측됐지만 인과관계는 미확정이다. 이것을 과거 startup 시간 초과 원인으로 확정하지 않는다.
- 실행 중인 로컬 Worker가 `dist/client`를 잠근 상태의 빌드 1회는 `EBUSY`로 실패했다. 소유 서버 종료 후 재빌드했다. 설치 도우미의 npm shim 경로 실패는 기존 Node/npm CLI로 `install:ci`를 실행해 해결했으며 lockfile은 바꾸지 않았다.
- 모바일 브라우저 에뮬레이션·접근성 트리/role·키보드·axe·스크린샷 확인이다. 실제 iPhone/VoiceOver, 초급 학습자 사용성 실험, 운영 계정/기기 간 동기화, 외부 폰트/AI 실서비스 품질은 이번 검증에 포함하지 않는다. 문구 간소화만으로 학습 효과 향상을 주장하지 않는다.
- startup·과거 401 응답 원인은 미확정이다. 로컬 가상 실패/로그인 응답은 원인 해결 증거가 아니다. 운영 v139 및 별도 PR #47 문서 변경은 그대로 보존한다.

## 위험·복구·후속 경계

위험은 표시 문구와 접기 UI, 친숙도 완료의 저장 완료 대기에 집중된다. 원문을 펼칠 수 있어야 하며 저장 실패 뒤 이동시키지 않아야 한다. 기존 서버 진단 코드·로그·관측 필드는 유지하고 개인 답안/문장을 진단에 추가하지 않는다. 새 운영 설정이나 마이그레이션은 없다.

배포는 별도 승인 작업이다. 이후 배포한다면 이 브랜치의 검증된 소스를 기존 Sites 절차로 게시한다. 되돌릴 때도 PR #47의 카드 종료를 포함한 소스로 앱 표시 변경만 되돌린다. 위치 테이블·학습 문서·revision·과거 백업을 삭제하거나 덮어쓰지 않는다. 기존 v139와 startup/401 미확정 기록을 유지한다.
