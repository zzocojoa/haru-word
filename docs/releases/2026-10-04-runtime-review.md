## 검토와 수정

- 처음 가져온 브라우저 QA가 과거 버튼·기록 문구를 사용해 Chromium에서 대기 실패했다. 실제 main의 **AI 참고 의견** 문구로 수정했고 최종 두 엔진이 통과했다. 제품 문구를 시험에 맞춰 되돌리지 않았다.
- Testing 검토에서 새 평가 프로필의 잘못된 요청이 400으로 거절되어도 검사가 통과할 수 있음을 발견했다. root-cause/control, reasoning/current·high 등 실제 프로필/variant와 설정을 사용하고 정확한 `evaluation_invalid_request` 및 제공자 호출0을 확인하도록 수정했다.
- 문법 적용 버튼 검사가 원문=교정문 조건만 사용하면 보호 로직 없이도 통과할 수 있었다. 별도 합성 교정 사례에서 위험 분석은 버튼을 숨기고, 역할만 안전하게 고친 양성 대조군은 버튼을 보이는 회귀를 추가했다. 보존 fixture는 수정하지 않았다.
- 테스트·유지보수·성능·보안/API와 독립 adversarial 검토의 잔여 지적은 0이다. 별도 문맥의 Codex 검토이며 다른 모델 간 교차 검토로 표시하지 않는다. 독립 검토에서 97개 경로/blob·자료 해시와 임의 키/단계/경로 공격 입력도 대조했다.
- 성능 검토의 메모리 내 minified bundle 비교에서 파서 +2,542B, 평가 API +2,459B이며 새 import 의존성은 없었다. 로컬 번들 크기 근거이며 원격 CPU나 청구 적합성 측정은 아니다.

별도 Codex CLI는 앞서 확인한 클라이언트/선택 모델 비호환을 반복 실행하지 않았다. 이 경로는 완료된 검토에 포함하지 않는다. 실제 iPhone, 현재 Free 계정 상태, 원격 CPU, 새 모델 정확도와 제공자 실연동은 이번에 검증하지 않았다.

## 출시 한계

공통 파서를 추가해도 평가 실행 경로나 입력 스키마는 활성화하지 않는다. 보존한 실험 후보를 다시 실행하려면 별도 범위 검토가 필요하다. 다음 게시 전에는 최신 Site와 후보 flag·평가 Secret 폐쇄 상태, 활성 학습/카드 경로, 데이터 호환과 복구 버전을 확인한다. 전체 운영 소스와 main이 같은 트리라는 주장은 하지 않는다.
