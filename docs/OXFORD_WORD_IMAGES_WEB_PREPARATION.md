## 실행·재개

체크아웃에서 Node22.13 이상과 기존 lockfile의 의존성을 사용한다. 새로운 이미지 API·키·결제는 필요하지 않다.

```powershell
npm run images:all:prepare
npm run images:all:verify
```

다른 원본 위치는 `--source "<승인 소스>" --assets "<원본 PNG 폴더>"`를 전달한다. `--output`은 현재 체크아웃의 `outputs/` 하위로만 지정할 수 있다. 예:

```powershell
npm run images:all:prepare -- --assets "C:/검증한 원본 폴더" --output "outputs/oxford-web/별도-가공-회차"
```

중단 후 같은 명령을 실행하면 개별 receipt와 파일 해시·디코딩을 다시 확인해 재사용한다. 기존 출력이 변조되었거나 source/recipe/encoder가 다르면 덮어쓰지 않고 중단한다. 실행 중인 PID의 lock이 있으면 동시 실행을 차단한다. 종료된 프로세스의 lock만 확인 후 회수한다. 원본이나 이전 결과를 지워 재개하지 않는다.

모든 항목이 통과하기 전에는 최종 연결 목록을 생성하지 않는다. 검증 완료 후 목록은 임시 파일을 거쳐 create-only 방식으로 확정한다. 동일한 목록은 재사용하고 다른 기존 목록은 보존한 채 오류를 반환한다. 검증 전용 명령은 WebP를 새로 인코딩하거나 누락된 최종 목록을 자동 복구하지 않는다. 매번 결과 보고서는 새 회차 파일로 남긴다.

## 연결 목록과 업로드 예시

목록에는 `entryId`, `word`, `pos`, `level`, `baseMeaning`, `sourceFingerprint`, 원본/변환 SHA, 원본/변환 크기, 바이트 수, 글자 예외 정책과 `objectKey`를 기록한다. 같은 철자의 다른 뜻을 합치지 않는다. 프롬프트·과거 시도·개인 문장·로컬 원본 경로는 배포 목록에 넣지 않는다. 현재 앱에는 전체 목록을 import하지 않으며, 시범20개가 사용하는 목록과 공개 파일도 변경하지 않는다.

업로드 목록의 한 파일은 다음 형태다. `objectKey`는 향후 저장소 키이며 **현재 열 수 있는 URL이 아니다**.

```json
{
  "entryId": "<항목 ID>",
  "file": "assets/<WebP SHA256>.webp",
  "objectKey": "oxford-images/v1/<WebP SHA256>.webp",
  "sha256": "<WebP SHA256>",
  "bytes": 25972,
  "contentType": "image/webp",
  "cacheControl": "public, max-age=31536000, immutable"
}
```

HTTP 값은 후속 업로드/제공 단계의 **요구 설정**이다. 현재 Sites에서 이 헤더가 적용됐다는 뜻이 아니며 v129의 MIME/캐시 한계는 그대로다. 실제 업로드 후 바이트 해시·MIME·캐시를 다시 확인해야 한다.

## 검증과 인수인계

도구 회귀 검사는 미승인/잘못된 ID/뜻/파일명·글자 예외·종횡비·손상 원본/출력·중단/재개·동시 실행·최종 목록 충돌을 확인한다. 전체 목록 메타데이터 검사는 실제 이미지 파일 없이 CI에서도3809개 교재 대응과 기존 시범20개 SHA 보존을 검사한다. 파일 디코딩·해시의 실제 결과는 별도 로컬 전체 보고서로 구분한다.

완료 시 확인할 항목:

1. prepare와verify가 각각3809개 원본/변환 디코딩·해시를 통과하고 변환본/연결 목록이3809개인지 확인한다.
2. A1/A2/B1/B2 개수가1077/990/903/839인지 대조한다. 동일 철자를 제외 대상으로 삼지 않는다.
3. 전체 테스트·타입·린트·빌드 결과와 현재 원본/원장/시범/운영 코드 보존을 기록한다.
4. WebP·`catalog.json`·`upload-manifest.json`·보고서를 함께 보관한다. 실제 업로드나 원본의 외부 백업은 이번 작업에 포함되지 않는다.

기록·API·DB·백업·Sites 설정/배포·관측 로그에는 변경과 마이그레이션이 없다. 브라우저 UI·실제 iPhone·독립 학습자 평가·Node24 CI는 이번 로컬 가공 검증의 범위가 아니다. 제작자의 승인과 파일 무결성 검사를 영어 의미 정확도 인증으로 표현하지 않는다.
