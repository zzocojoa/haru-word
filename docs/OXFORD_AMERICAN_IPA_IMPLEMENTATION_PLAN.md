# 미국식 IPA 사전 v3 앱 연결 계획

작성일: 2026-10-19

상태: PLAN 완료 → 승인 후 구현·로컬 검증 완료 (미배포)

방법: pdca-framework

기준: PR #51 병합 main `0c16cc83dfe74345506eb00e018b16542e1be640`

이 문서는 대화에서 확정한 계획을 저장한 것이다. 최초 저장 요청은 앱 구현·커밋·푸시·배포·설정 변경을 포함하지 않았다. 이후 ‘구현 승인’에 따라 별도 `codex/american-ipa-display` 작업 영역에서 로컬 구현·검증을 완료했다. 기본 폴더의 원래 계획과 미커밋 변경은 그대로 보존했다. [완료 근거와 한계](OXFORD_AMERICAN_IPA_IMPLEMENTATION_VERIFICATION.md)를 참조한다. 아래 항목은 승인된 계획의 계약이다.

## 1. 목표와 기준

사전 v3의 발음을 **현재 단어의 뜻·품사에 맞춰 학습·상세 화면에 표시**한다. 기존 듣기 기능과 학습 기록은 유지한다.

- 기준: PR #51이 병합된 `main@0c16cc8`.
- 읽기 전용 확인 결과: **3,809항목·3,837개 발음**, 복수 발음 26항목 모두 현재 교재와 일치했다.
- 기존 지연 로딩 검사 `node --experimental-strip-types --test tests/learning-chunks.test.mjs` 2개 통과(exit 0). 계획 검토 당시 미커밋 175개 항목·index·로컬 브랜치 보존을 확인했다.
- 계획 검토 당시에는 앱·배포·설정을 변경하지 않았다. 이후 로컬 구현의 상태와 별개로 운영 **v140**, startup·401 원인 **미확정**을 유지한다.

## 2. 표시 위치와 동작

사용자가 선택한 **학습·상세 중심**, **이미지 뒷면 즉시 표시**, **복수 발음의 조건 전체 표시**를 적용한다.

| 화면 | 표시 방식 |
|---|---|
| 단어 학습 | 영어 단어 아래, 이미지 미리보기와 듣기 영역보다 앞에 표시 |
| 문장 작성 | 목표 단어 아래에 표시 |
| 완료한 학습 다시 보기 | 해당 기록에 저장된 뜻과 일치하는 발음을 단어 아래에 표시 |
| 단어 편집창 | 단어 제목 아래 스크롤 본문의 첫 부분에 표시하고, 뜻 선택·초안 변경에 따라 즉시 갱신. 긴 발음 조건이 입력란을 가리지 않게 한다. |
| 이미지 연습 | 뒷면의 영어 단어 아래 IPA, 그 아래 한국어 뜻·품사 표시 |

- 단일 발음은 `미국식 /…/`로 간결하게 표시한다. 복수 발음은 `원형·현재 /rid/`, `과거·과거분사 /rɛd/`처럼 사전 순서와 적용 조건을 모두 유지한다.
- 오늘 목표 목록·전체 단어장 목록·친숙도 확인·회상 단계에는 새 IPA를 추가하지 않는다.
- 이미지 앞면에는 IPA와 답안을 DOM·접근성 이름에도 노출하지 않는다. 뒤집기 버튼 안에는 텍스트만 넣고, 듣기·사전 링크는 버튼 밖의 기존 접힌 발음 영역에 유지한다.
- 별도 표시 설정이나 외부 폰트를 추가하지 않는다. 기존 디자인과 시스템 폰트 대체 경로를 사용한다.

## 3. 데이터 연결과 호환성

**사전 Markdown → 검증·변환 스크립트 → 화면용 정적 데이터 → 공통 IPA 표시**로 연결한다.

- [사전 v3](OXFORD_AMERICAN_IPA_DICTIONARY.md)를 편집 원본으로 유지한다. 실행 중 Markdown 파싱이나 외부 사전 조회는 하지 않는다.
- 생성기는 화면용 경량 JSON과 출처 보존용 공개 JSON을 만든다. 화면용에는 ID별 `ipa·usage`를, 공개 자료에는 식별 정보·`sourceIpa`·출처 URL·검토 방법·날짜·비고·정규화 버전·기존 라이선스 고지를 보존한다.
- 기존 생성기와 같은 `--check` 방식을 사용한다. ID 누락·중복, 교재 불일치, 발음과 원문 개수 불일치, 잘못된 형식, 미정의 출처, 오래된 생성물은 검사 실패로 처리한다. 입력 지문은 기존 CRLF 정규화 방식을 따른다.
- 내부 조회 함수 `resolveWordIpa(word, selectedMeaning)`는 **ID·철자·원문 표제어·품사·현재 뜻**이 일치할 때만 발음을 반환한다. 뜻은 앞뒤 공백만 허용하며 대소문자·내부 공백을 임의로 합치지 않는다. 개인 단어·다른 뜻·알 수 없는 ID에는 IPA를 표시하지 않는다.
- [공통 발음 컴포넌트](../app/word-pronunciation.tsx)에서 IPA 텍스트와 듣기 기능을 분리한다. 기존 16개 동형이의어의 사전 우선 정책과 일반 단어의 기기 음성 버튼은 유지한다. 기존 안내 데이터의 IPA를 중복 표시하지 않는다.
- 화면용 데이터는 기존 학습·편집창의 지연 로딩 경로에만 포함한다. 홈·목록의 초기 번들에 들어가지 않도록 검사한다. 출처 전체 자료는 앱 번들에 넣지 않고 ‘학습 방식과 자료 출처’에서 연결한다.
- `Word`, `Content`, 사용자 기록·백업 형식과 서버 API는 변경하지 않는다. IPA를 학습 기록에 저장하지 않으며 DB 마이그레이션도 필요하지 않다.

## 4. PDCA 구현 순서

각 단계는 **실패하는 테스트 하나 → 최소 구현 → 통과 확인 → 필요한 정리** 순서로 진행한다. 선행 대규모 리팩터링은 하지 않는다.

1. **데이터 변환**
   - 사전 파싱·교재 일치·출처 보존·재현성 검사를 먼저 작성한다.
   - 생성기와 두 산출물을 추가하고, 생성·검사 명령을 npm 스크립트와 빌드 검사에 연결한다.
   - 기존 교열의 고정 기대값을 저장소 내 회귀 자료로 옮겨, 무시되는 로컬 작업 파일 없이 검증할 수 있게 한다.

2. **조회와 공통 표시**
   - 뜻·품사·표제어 일치 및 불일치 테스트부터 구현한다.
   - 공통 IPA 텍스트 표시를 추가하고, 기존 듣기 분기와 가족 관계 안내를 보존한다.
   - 사전 v3의 정규화에 맞춰 기존 `/riːd/` 등 표시 기대값을 갱신한다.

3. **화면 연결**
   - 위 표의 다섯 화면에 적용한다.
   - 이미지 카드에는 텍스트 전용 표시를 사용하고, 발음 영역에서 IPA가 중복되지 않게 한다.
   - 뜻 수정·다른 카드 이동·창 재개 시 이전 IPA가 남지 않는지 확인한다.

4. **CHECK·ACT**
   - 아래 검증을 완료하고 결과·실패·미검증 범위를 기록한다.
   - README·발음 정책·테스트 안내에 데이터 갱신 명령과 출처를 반영한다. 이 저장소에는 `CLAUDE.md`가 없으므로 이를 새로 만들지 않는다.
   - 범위 밖 문제가 발견되면 별도 기록하고, 다음 작업에 적용할 개선점만 제안한다. 커밋·PR·병합·배포는 별도 요청 범위로 남긴다.

## 5. 검증과 완료 기준

- **데이터:** 3,809개 ID·3,837개 발음·26개 복수 항목, 출처 및 조건 보존, 생성 재현성, CRLF/LF 동일성, 입력 변경 시 검사 실패.
- **발음 선택:** `read`, `close`, `record`, `live`, `lead`, `wind`, `tear`, `house`, `wound`, `transfer`, `online`, `IT/it`, `a, an`과 기존 115개 교열 회귀 사례.
- **사용자 뜻 보호:** 편집 초안·다른 뜻·개인 단어에서는 IPA 제거, 원래 뜻으로 복귀하면 복원. 과거 학습은 현재 편집값이 아닌 해당 기록의 뜻으로 판단. 명시적인 빈 뜻을 기본 뜻으로 대체해 IPA를 표시하지 않는다.
- **브라우저:** 로컬 가상 계정의 Chromium·WebKit에서 다섯 화면, 이미지 양방향 뒤집기·앞면 재개·위치 저장, 키보드·초점 복귀·접근성을 검사한다. 320/390/1440px와 글자 200%에서 긴 조건도 잘리지 않아야 한다.
- **회귀·로딩:** 기존 발음·기기 음성·이미지 연습·재개·지연 로딩 QA를 실행한다. IPA 표시·뒤집기만으로 학습/위치 쓰기가 발생하지 않아야 하며, 홈에서 IPA 자료·외부 사전을 요청하지 않아야 한다.
- **최종 명령:** 생성기 `--check`, `npm test`, `npm run check:grammar-review`, `npm run typecheck`, `npm run lint`, `npm run build`. 기존 경고와 새 실패를 구분해 기록한다.
- 실제 iPhone·VoiceOver·음원 청취는 로컬 자동 검사와 구분한다. 이번 기능 검증을 startup·401 원인 규명으로 표현하지 않는다.

구현은 최신 main 기반의 별도 작업 영역에서 진행해 기존 미커밋 변경을 보존한다. 복구는 IPA 관련 변경만 되돌리는 방식이며 학습·위치 데이터 변환은 없다. 각 구현 단계에 들어가기 전에 **PDCA DO 프롬프트를 읽고** 진행한다.
