# 공개 참조 6문항 묶음 진단 제안 · 2026-11-07

**설계·오프라인 구현 완료, 새 유료 범위는 미승인이다.** 기존 승인 범위 `public-g12-n04-diagnostic-only`의 실제 6응답을 재호출하지 않는다. 현재 비용은 US$0.843789, 캠페인 한도는 세전 US$5 그대로다. 이 제안은 남은 예산에 새 US$5를 더하지 않는다.

## 무엇을 확인하는가

다음 공개 참조 검토에서 모델이 단순한 오류와 근거 부족을 구별하는지 진단한다. 기존 `reference-controls-v2.json`의 6문항·7차원·중대 오류 5개 플래그와 제안 기대값을 그대로 사용한다. 기대값은 아직 같은 작성자의 제안이며 영어 정답으로 인증되지 않았다.

| 문항 | 관찰할 내용 |
| --- | --- |
| 정상 주어·동사 일치 | 정상 문장을 잘못 고치지 않는지 |
| 잘못 붙인 자연스러움 라벨 | 복수 주어에 붙은 단수 동사 오류를 놓치지 않는지 |
| 목표 불일치 | 동사를 요구한 과제에서 명사로 답한 기록을 구별하는지 |
| 부정 의미 유실 | 교정에서 `not`이 사라진 것을 발견하는지 |
| 거짓 출처 귀속 | 출처가 말하지 않은 규칙을 출처의 주장으로 받아들이는지 |
| 앞선 대화 없는 답변 | 주어지지 않은 사건을 상상해 확정하지 않는지 |

Sol·Terra·Astra 각각 두 순서로 검토하므로 **문항 판정은 36개**다. 과거 방식은 36개 요청에서 같은 기준 기록을 매번 반복했다. 새 방식은 요청당 6문항과 공통 기준 기록 1개를 넣어 총 6개 응답을 받는다. 문항 판정 36개와 공통 기준 판정 6개를 구분한다. 과거 36개 기준 판정을 측정한 것처럼 복제해 세지 않는다.

공통 기준을 앞/뒤로 옮기고 문항 순서를 역전한다. 출처·과제·입력·초안은 원본 그대로다. 각 문항의 노출 목록은 공유 사전과 `[기본 항목 번호, 원래 ID, 가족 ID]`로 저장하고, 복원 후 원래 지문과 일치하는지 검사한다. 관련 없는 것으로 보이는 노출 항목도 삭제하지 않았다. 기존 36본문 총 1,036,536바이트 → 새 6본문 총 439,384바이트, 요청당 73,230–73,232바이트다. **바이트 수를 실제 토큰 수라고 간주하지 않는다.**

묶음 형식의 간섭과 위치 효과는 실제 미측정이다. 과거 2기록 비교 방식과 동등하다고 주장하지 않는다. 모든 문항이 공개·노출된 자료여서 새 비노출 문항을 구별하는 특이도도 이 진단만으로 입증할 수 없다. 통과해도 원래 12개 보정 기준을 자동 승인하거나, 참조 검토자의 역할 자격·영어 품질·출시를 승인하지 않는다.

## 실제 토큰 기준 비용과 중단 조건

[공식 Standard 요금](https://developers.openai.com/api/docs/pricing)을 다시 확인했다. 캐시 쓰기를 끄고 지역 처리 10% 여유를 포함한다. 출력 한도 **4,096은 유지**하며 [출력과 추론 토큰을 포함](https://developers.openai.com/api/docs/guides/reasoning)한다. 제품 생성 한도와 기존 평가 기준을 낮추지 않는다.

실행 범위가 승인되면 [공식 계산 API](https://developers.openai.com/api/docs/guides/token-counting)에 모델·지시문·입력·추론·전체 출력 스키마를 동일하게 보내 6본문의 실제 입력을 측정해야 한다. **요청당 50,000토큰은 예산상 허용 천장이지 측정값이나 모델 최대 입력량이 아니다.** 하나라도 초과하거나 계산 결과·본문 연결이 불명확하면 생성 요청을 시작하지 않는다.

| 예약 항목 | 요청당 입력 50,000 이하일 때의 금액 |
| --- | ---: |
| 기존 비용·미정 예약 | US$0.843789 |
| 새 생성 6회 최대액 | US$2.015728 |
| 새 계산 6회 비용 여유 | US$2.015728 |
| 조건부 캠페인 예약 상한 | **US$4.875245 / US$5** |
| 조건부 남은 여유 | US$0.124755 |

계산 API의 별도 단가가 명시됐다고 확인하지 못했다. 계산을 무료로 처리하지 않고, 6회 각각 입력 50,000·출력 4,096의 동일 모델 생성액을 여유로 계속 잡는 방법이다. **게시된 모델 요금에 따른 여유이며, 계산 API 전용 요금이나 최종 청구액의 보증은 아니다.** 청구서도 미확인이다. 공식 지출 제어 예제의 가상 가격을 실제 단가로 사용하지 않았다.

각 실제 입력이 20,000인 경우는 US$4.017245라는 별도 시나리오일 뿐 예상값이 아니다. 실제 계산 전에는 이 금액을 견적처럼 사용하지 않는다. 계산료 여유를 임의 환급하거나 과거 닫힌 원장을 재개하지 않는다.

새 실행에는 별도 한 번 실행 표식·원장·실제 계산 영수증·전체 요청 지문·원문 캡처를 연결한 수집기 검증이 필요하다. 현재 모듈은 순수한 준비·비용 시나리오·응답 검사기이며 키 접근과 전송 기능이 없다. 설계 범위를 승인하더라도 이 수집기 조건을 건너뛰지 않는다. 불명 비용·미완성 응답·모델/요금 계층 불일치·중단은 증거와 예약을 보존하고 보류하며 자동 재시도나 대체 모델은 없다.
