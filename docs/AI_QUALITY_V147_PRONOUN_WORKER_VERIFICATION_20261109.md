# 대명사 설명의 화면·저장 검증

이전 로컬 수정판과 대명사 설명을 보완한 후속 수정판의 실제 빌드를 각각 루프백 Worker에서 실행했다. 두 빌드에 동일한 문법 API 요청과 보관 응답을 주입했다. 비교한 5쌍은 대명사 교정에 대한 Sol·Terra·Astra 응답 3쌍, `skillfully` 교정 1쌍, 시점이 불분명한 조동사 문장의 교정 보류 1쌍이다. 같은 쌍의 제공자 요청 본문과 주입한 응답은 각각 지문이 일치했다.

| 확인한 동작 | 결과 |
| --- | --- |
| 문법 교정과 설명 | 두 빌드에서 교정문·판정이 같았다. 후속 빌드에서 대명사 설명 3건만 바뀌었다. |
| 저장·재조회 | 총 10건에서 요청 영수증과 학습 상태의 피드백을 다시 읽었다. 처음 답과 관찰 답을 보존했다. |
| 재시도와 계정 경계 | 동일 요청 ID 재전송 10건에서 추가 호출은 0건이었다. 다른 합성 계정에는 피드백을 반환하지 않았다. |
| 실제 빌드 화면 | Chromium·WebKit 각각에서 두 버전의 저장 피드백을 확인했다. 후속 빌드의 대명사 설명이 표시됐고 화면을 열 때 추가 호출은 없었다. |

첫 실행은 로컬 SQLite 파일을 열지 못했다. 새 로컬 DB를 더 짧은 작업 폴더 경로에서 실행하자 통과했다. 화면 자동 검사에서는 수업 그룹이 접혀 있음을 확인하고, 실제 ‘전체’ 수업 버튼으로 그룹을 펼치도록 고쳤다. 최종 Node 24 검사는 종료 코드 0이고, 두 소유 Worker와 포트의 종료를 확인했다. 기존 빌드와 후속 빌드의 파일 지문을 전후에 대조했다.

이번에는 보관 응답을 사용했다. 새 모델 호출·키 읽기·운영 학습 기록 변경은 0이다. 결과를 T15.2·15.3에 연결했다. 새 모델 생성 품질, 운영 합성 계정 점검(T38), 예비·확인 평가와 출시는 각각 별도 승인·검증 단계에 남는다.
