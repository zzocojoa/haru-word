# 참조 문항 작성·검토와 토큰 사전 확인 계약 · 2026-11-07

상태: **T34 문서 계약 초안·미승인·미구현**. API 연결 코드 변경·키 유무 검사·키 읽기·실제 AI/토큰계산 API 호출·추가 과금 승인/사용은0이다. 사람 검토자 섭외는 조건이 아니다. 기계 판독 원본은 `.taskmaster/docs/ai-quality-v147-reference-readiness-draft.json`이다.

## 이번에 확인한 빈틈

현재5역할 실행기의 참조 작성 fixture는 이미 있는 입력을 `sentence,target,criterion`으로 되돌린다. 참조 export도 그 문장/대상이 기존 입력과 같아야 한다. 이는 로컬 전송·예산·원장 검증용 계약이며 **새60문항의 입력·문맥·허용 교정·출처를 작성하는 실제 계약의 구현 근거는 아니다**. 기존 T22 완료는 그 로컬 범위로 유지하고, 실제 계약/본문 준비는 T34/T24 관문으로 남긴다.

현재 referenceReview fixture의 제품 피드백용5차원 점수도 참조 작성 검토에 그대로 옮겨 검증됐다고 볼 수 없다. 실제 참조 검토용 구조·통제·exporter의 명세가 필요하다. 현재 API/제품 코드를 이 문서 작업으로 변경하지 않았다.


현재 순수 출력 검증기는 ID의 일반 정규식 패턴을 지원하지 않아 새 스키마를 `W3_OUTPUT_PATTERN`으로 보류한다. 읽기 전용 대조로 확인했으며 기존 검증기는 변경하지 않았다. 표준 JSON Schema에서 구조가 유효하더라도 현재 실행기·공급자와 호환된다는 뜻은 아니다. 해당 어댑터의 구현·검증도 실제 실행 전 관문에 포함한다.

## 작성 결과 데이터 계약

작성자는 고정한 caseId·assignmentHash·domain·targetKey·구조적 가족 조건·길이/난도·허용 sourcePack·노출 목록을 받는다. 후보/기준 결과·기존 점수·구현 결함별 정답은 보지 않는다. word/POS/뜻 또는 문법 수업 기준은 고정 카탈로그 바인딩을 따른다.

작성 결과에는 실제 문장, 입력 문맥 종류/설명, 원문 목표/문법/추가 문맥 판정, 최소 교정의 허용 예시, 판정 기준, 허용 출처ID, 근거 수준과 불확실성이 필요하다. JSON Schema 외에 바인딩·Unicode·의미·출처·노출 검증을 따로 요구한다. 가족ID가 새롭다는 AI 주장이나 이름/단어 치환으로 독립 표본 수를 늘리지 않는다.

입력 `contextKind`는 sentence/reply/title/command다. 모델의 `contextNeeded`는 none/message/time/quantity/target_meaning/relationship로 별개다. 문장2000·상황500의 기존UTF16한도를 보존한다. 자연문은 원문을 유지하고, 문법 uncertain은 안전한 교정을 강제하지 않는다. 목표만 불확실해도 독립적으로 정당한 문법 교정은 가능하다. 교정 예시는 완전한 문자열 정답 목록이 아니며 다른 안전한 동등 교정도 평가할 수 있어야 한다.

출처ID는 미리 확인한 허용 pack 안에서만 선택한다. 모델이 새URL을 만들어 증거로 승격하지 못하게 한다. URL이 있다는 사실이나 AI가 적은 source-supported라는 이름만으로 전체 문항의 정답성을 인정하지 않는다. AI 합의는 그 수준을 유지하며 근거 없는 확신은 보류한다.

## 참조 검토·통제·export 계약

생성 모델을 제외한 두 모델이 배정 일치·입력/대상·원문 라벨·최소 교정/의미·근거 수준의 정직성·모호성·노출/가족 조건을 검토하도록7차원 초안을 만들었다. 임베디드 통제 후보는 각 요청에 새 초안과 알려진 참조 통제를 익명2항목으로 넣고 순서를 고정 무작위화하는 방식이다. 예상 통제 점수·생성자·다른 점수는 숨긴다. **이 방식은 아직 선택·검증·실행되지 않았다.** 피드백용12증인 보정이 이 새 참조 역할을 검증했다고 주장하지 않는다.

문항당 작성1+검토2의 기본 구조는 유지하되, 별도 자격 확인 호출 등이 필요하면 실제 요청·본문·토큰·금액·승인 상한을 다시 계산해야 한다. 이를 기존2052에 몰래 포함하지 않는다. 통제와 두 검토의 불일치·불확실·누락·중대 플래그는 참조 수용을 막는다. 스키마를 통과한 문장 속 지시문도 안전하다고 단정할 수 없으며 실제 모델의 편향/지시문 통제 검사가 필요하다.

작성 레코드16KiB·관련 sourcePack8KiB·기준문2000자·허용교정예시2개·출처4개는 검토용 결합 크기 제한안이다. 현재 구현한 한도가 아니다. 초과 시 유료 파생 검토 전에 보류하고 원문을 보존하며, 의미를 줄여 잘라 넣거나 실패 문항을 교체/재시도하지 않는다. 실제 corpus가 이 조건과 지원 범위를 충족하는지 검증해야 한다.

export는 초안이 실제로 작성한 문장/문맥을 다음 평가 입력으로 사용하고, 신뢰한 대상 바인딩으로 grader target을 만든다. 닫힌 참조 원장·작성/두검토/통제 원문과 영수증·배정/sourcePack/노출 지문을 함께 넘긴 후 새 실제 corpus를 동결한다. 기존 문장 되풀이용 export를 실제 작성 완료로 대체해 사용하지 않는다.

## 토큰 수·비용 사전 확인

공식 [토큰 계산 안내](https://developers.openai.com/api/docs/guides/token-counting)와 [count API](https://developers.openai.com/api/reference/resources/responses/subresources/input_tokens/methods/count)를 검색 후 읽었다. API는 입력 형식·지시문·스키마 등에 대한 모델 입력 토큰 수를 반환한다. 생성 요청의 model/instructions/input/reasoning/text를 정확히 투영하고 **전체 생성 본문 지문도 함께** 묶어야 한다. 출력상한·store/stream/service_tier는 count 투영에 없더라도 가격/동작 바인딩에서 유지한다.

반환값을 받지 않았거나 본문/부모/옵션이 바뀌었거나 상한을 넘으면 생성 전에 보류한다. 파생 검토는 부모 원문을 채운 실제 최종 본문을 세며 빈 템플릿으로 대신하지 않는다. 문자수/4나 바이트 수를 확정 과금 토큰으로 취급하지 않는다.

공개 보정12증인×3모델×2순서의72본문을 기존 순수 컴파일러로 읽기 전용 분석했다. 전체 본문은5039–5574바이트이며 서로 다른 runId/salt에서도 본문 지문이 같고 expectedGrade 메타데이터가 요청에 없다. 원문을 실행 가능한 묶음으로 저장하지 않고 지문·크기만 기록했다. **실제 입력 토큰 수는 미측정**이며 출력4096 상한도 변경하지 않았다.

확인한 공식 문서만으로 count API의 과금 여부는 확정하지 못했다. 무료라고 가정하지 않는다. 실제 API 접근·자격증명 선택·count 요율/한도·본문/옵션/가격·새 승인까지 확인하기 전에는 count나 모델 요청을 실행하지 않는다. 기존 승인·닫힌 잔액은 사용하지 않는다. 이 문서는 금액 승인 요청이나 결제 가능한 견적이 아니다.
