# T26.2·T34.4 화면 채점 기록 재현

이전 화면의 채점 기록을 읽을 때 과거 제품 소스를 다시 검사하던 모듈 초기화가 실행을 막았다. v6·v7의 고정 기준 식별자를 과거 요청에서 확인해 사용하도록 바꿨다. 과거 기준으로 새 요청을 만드는 경로에서는 제품 소스 지문과 생성한 기준의 지문을 계속 검사한다.

| 확인 항목 | 결과 |
| --- | --- |
| 과거 묶음 채점 | 저장한 실제 응답 3개로 당시 비교 6건의 판정을 그대로 재현 |
| 과거 개별 보정 | 실제 응답 72개로 당시 기준 일치 71/72를 그대로 재현 |
| 현재 화면을 넣은 보정 본문 | 18개 일치, 54개 변경. 바뀐 본문에 과거 응답을 연결하면 검사에서 거절 |
| 이전 비용 범위 재실행 | 이미 정산된 범위의 재예약을 차단 |

합성 수집은 이전 실행 증거와 분리한 폴더에서 검사했다. 정상 입력은 합성 수집 후 정산됐고, 입력 상한 초과 시 모델 전송 전에 중단됐다. Node 22·24의 화면 채점 검사 각 5개, 보정·개정 집계 검사 7개, 변경 스크립트 ESLint가 통과했다.

71/72는 과거 화면의 실제 채점 결과다. 현재 화면의 정식 채점 자격과 실제 예비평가는 보류 상태다. 새 AI 요청·입력 토큰 계산·키 읽기는 각각 0회이며, 예산 원장 두 사본과 과거 응답의 지문을 대조했다. 원본 코드, 재현 검사와 요약은 `outputs/ai-quality-v147-implementation-20261106/phase142/`에 보존했다. [현재 화면의 54개 변경 내역](AI_QUALITY_V147_CURRENT_SCREEN_CALIBRATION_20261109.md)
