# 별도 로컬 후보의 정상 교정 오거절 수정

동결한 평가 후보에서 별도 로컬 사본을 만들었다. 992개 소스 파일을 대조했고 수정 범위는 `lib/feedback-word-forms.ts`, `lib/judgment-correction.ts`, `tests/ai-quality-morphology.test.mjs`다.

같은 조동사와 문장 나머지 부분을 유지하면서 교재 동사의 현재형이 올바른 진행형으로 바뀌는 경우를 판별한다. 사전으로 확인한 부사 네 쌍에는 인용문·연결동사 보어를 보호하는 제한을 적용했다. `checks → checking`과 `reckless → recklessly`처럼 단어 형태를 고치는 두 사례를 재현했다. 수량·부정·시제·참여자·대상 변경과 잘못 만든 형태는 회귀 검사에 포함했다. [앞선 시험안 비교](AI_QUALITY_V147_CORRECTION_GUARD_COMPARISON_20261109.md)

수정 후보의 로컬 Worker에 기존 합성 응답 180건을 다시 넣었다. 요청 본문 180개는 동결 후보의 기록과 바이트 단위로 일치했다. 이전에 막혔던 6건의 저장·재조회가 성공했고, 동일 요청을 다시 보내도 제공자 호출이 늘지 않았다. 두 사례의 저장 응답을 Chromium과 WebKit의 피드백 화면에 표시했다. 실제 모델 호출은 0건이다.

공유 의존성을 막는 검사가 최초 빌드를 중단해 별도 의존성 사본과 portable 실행 프로필을 구성했다. 병렬 실행에서 시간 제한에 걸렸던 잠금 경합 검사는 단독 전체 재실행에서 통과했다. 최종 단위 테스트 893/893, 타입 검사·린트·빌드는 종료 코드 0이다. 기존 린트 경고는 15개다.

동결 후보와 새 평가 문항은 별도 보관한다. 이 로컬 사본의 결과는 정식 예비평가나 출시 판정으로 집계하지 않는다.
