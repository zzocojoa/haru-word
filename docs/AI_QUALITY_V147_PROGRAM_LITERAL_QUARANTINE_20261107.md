# 개발 코드 문자열의 용도와 새 참조 평가 유입 차단

기존123개 테스트 프로그램에서 수집한 **629곳·중복 제거433개 문자열 후보**를 원래 코드의 AST 위치와 연결했다. 새 참조 초안의 원문·맥락·허용 교정안이 이 문자열과 정확히 일치하면, 받은 응답과 비용 기록을 보존하고 후속 검토의 토큰 계산·모델 요청 및 참조 채택을 차단한다. 이 작업은 평가 자료의 개발 노출을 통제하기 위한 것이다. 제품 영어 판단 개선이나 전체 품질 합격을 입증하지 않는다.

## 분류의 의미와 범위

분류는 코드에서 사용된 위치에 대한 근거다. 변수명이나 속성명만으로 실제 학습 입력의 역할·영어 정답·문법 자연스러움을 확정하지 않는다. 각 후보에 파일 hash, UTF-16 시작/끝, 원문 조각 hash, 부모 구문, 호출 인자/배열 위치/선언 이름과 적용 규칙을 보존했다. 프로그램·SQL·테스트를 실행하지 않았다.

| 코드상의 용도 | 위치 수 |
| --- | ---: |
| sentence/original/before라는 이름의 위치 | 156 |
| 교정안 이름의 위치 | 72 |
| 예문·답·문항·표현 이름의 위치 | 22 |
| 설명·메모·맥락·메시지 이름의 위치 | 24 |
| sqlite.prepare의 직접 SQL 인자 | 35 |
| assertion의 기대값/메시지 위치 | 28 |
| 그 외 함수 호출 인자 | 112 |
| 의미 역할을 확정하지 않은 반복 바인딩 | 130 |
| 그 외 변수/속성 위치 | 50 |
| 합계 | **629** |

특히 `a/b` 같은 변수명을 원문/교정안으로 추측하지 않는다. AST의 실제 반복 바인딩과 배열 위치를 기록한다. 이 분류는 런타임 데이터 흐름 분석이 아니며, 기존 감사의 한 줄·마침표·영어 단어2개 이상 등 정적 후보 필터를 넘는 모든 실제 입력의 목록도 아니다.

433개 모두를 로컬 hash 격리 목록으로 유지한다. SQL이나 설명처럼 보이는 항목 및 역할이 불확실한 항목도 삭제해 새 영어 자료라고 통과시키지 않는다. 영어 정답표로 사용하거나 모델에게 원문 목록을 보내지 않는다. 모델의 학습 데이터에 포함됐다고 주장하는 것도 아니다. 이번 작업은 이 프로젝트의 개발 노출에 한정한다.

기존 전역426개와 유한 템플릿69개를 보존했다. 새433개 중399개가 전역426개 밖이고, 템플릿69개와도 겹치지 않는 추가 문자열은 **398개**다. 세 목록의 중복을 제거한 정확한 표면형은 **893개**다. 이 수는 독립 문장 표본 수나 오류 가족 수가 아니다.

## 실행 경계와 재현 방법

새 `.taskmaster/scripts/ai-quality-v147-program-literal-roles-v1.mjs`가 기존 감사와 실제123개 원본 hash를 대조해 분류한다. `program-literal-roles-v1.json`은 로컬 근거, `program-literal-quarantine-index-v1.json`은 문장 원문이 없는 hash 목록이다. `.taskmaster/scripts/ai-quality-v147-program-literal-exclusion-v1.mjs`가 고정 목록과 출처를 확인한다.

새 참조 준비 입력은 `withProgramLiteralPolicyV1(inputs)`로 필수 정책과 index hash를 연결하고, contract/collectionPolicy/seal을 다시 동결한다. 입력 토큰 계산이 필수인 REFERENCE_V4 프로필에만 연결한다. 새 정책을 넣지 않은 기존 합성 프로필은 과거 비교용으로 유지한다. 이를 현재 새 참조 자격으로 승격하지 않는다. 이후 T24의 새 실제 참조 동결은 이 정책을 포함해야 한다.

1. 소유권을 열기 전에 정책·전체433개/629출처·고정 catalogue·123개 원본을 확인한다. 누락/축소/사적 필드/필수 조건의 변경은 전송 전에 보류한다.
2. 전송 직전과 원문 저장·정산 후에 출처와 index 결합을 확인한다. 대기 중 원본이 바뀌어도 받은 응답을 버리지 않는다.
3. `input.sentence`, 비어 있지 않은 `input.contextNote`, `acceptedCorrectionExamples` 각각을 같은 정규화/hash로 대조한다. 일치하면 `PLX1_KNOWN_PROGRAM_LITERAL`로 후속 검토 계산 전에 중단한다.
4. 보고·읽기 전용 재조회·인계에 일치 필드/출처 ID·부분 범위를 남긴다. 이미 수집한 옛 실행의 완전한 캡처여도 현재 정책에 어긋나면 참조로 채택하지 않는다.
5. 이미 닫힌 실행과 실제 CLI 종료 후에는 같은 UUID를 다시 보내지 않는다. 모르는 문자열은 신선함·영어 정확도의 합격증으로 바꾸지 않으며 기존 전역 미해결/분쟁 기준도 유지한다.

관련123개 프로그램이 바뀌면 기존 고정 목록은 실행을 보류한다. 새 코드의 후보와 용도 근거를 다시 대조해 새 버전으로 동결해야 하며, hash 오류를 무시하거나 목록을 자동 축소하지 않는다. 목록의 출처 경로는 실제 작업 원본 SOURCE 기준이다. ROOT의 제품 테스트를 SOURCE와 맞추려고 덮어쓰지 않는다.

공식적인 새 미공개 corpus나 오류 가족으로의 일반화 자격은 아직 없다. 동적 코드·변환·조각·다른 경로·과거 보관 자료 및 구조적 유사성의 완전한 검사는 남아 있다. 이번의 정확한 표면형 일치 검사를 문장 의미나 가족 수준의 독립성 증명으로 해석하지 않는다.
