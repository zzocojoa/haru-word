## 1. 목표와 확정 범위

- 현재 교재의 **3,809개 학습 항목에 이미지 한 장씩** 제작한다. 같은 철자라도 품사·수준·기본 뜻이 다른 항목은 구분한다.
- **성인용 간결한 삽화**로 통일한다. 이미지에 영어·한글·숫자·라벨·예문·워터마크를 넣지 않는다.
- **20장 시범 제작 → 사용자 확인 → 전체 순차 제작·검수** 순서로 진행한다.
- 이번 범위는 이미지와 연결 목록의 준비까지다. 첨부한 두 화면의 코드 수정, 이미지 호스팅과 운영 배포는 후속 작업으로 분리한다.
- 개인 단어와 사용자가 추가·수정한 뜻은 제외한다.

## 2. 새 브랜치와 계획 문서

- 생성 이미지는 기본 생성 위치에서 주 작업 폴더의 **`outputs/oxford-images/<교재해시>/`**로 복사한다. Git 제외 폴더에 원본과 시도별 파일을 보존하며, 기존 파일을 덮어쓰지 않는다.

계획 확정 당시에는 계획 모드로 브랜치 생성·파일 저장·이미지 호출을 실행하지 않았다. 최초 문서 저장 요청에서는 새 브랜치와 계획 문서만 준비했다. 이후 사용자의 “다음 단계 진행” 요청으로 아래 시범 20장 제작을 진행했다.

## 3. 제작 기준과 시범 20장

- 단어 ID, 품사, 수준, 기본 뜻을 기준으로 장면을 작성한다. 기존 표현·예문은 의미 확인에 사용하며, 철자만 보고 장면을 정하지 않는다.
- 공통 스타일은 단순한 형태, 절제된 색, 깨끗한 배경, 세로형 구도로 고정한다. 어린이·교실·장식 소품을 기본 요소로 추가하지 않는다.
- 구체적인 단어는 사물이나 행동을 중심으로 표현한다. 기능어·추상어는 한 이미지 안에 **최대 두 개의 관계·대비 장면**을 허용한다.
- 시범 항목은 다음 20개로 고정한다.
  - 기본 6개: `apple`, `bicycle`, `climb` 동사, `bridge`, `careful`, `group`.
  - 뜻 구분 8개: `about` 전치사/부사, `bank` 은행/강둑, `light` 밝은/가벼운, `record` 기록/녹음하다.
  - 기능·추상 6개: `under`, `because`, `a, an`, `the`, `would`, `freedom`.
- 첫 `apple` 이미지로 스타일 기준을 만들고 나머지 이미지에 참고 자료로 전달한다. 시범 이미지는 채팅 안에 직접 표시해 확인받는다.
- 시범 검수 결과와 사용자 피드백을 계획 문서에 반영한 뒤 전체 제작 기준을 고정한다. 사용자 확인 전에는 나머지 항목을 생성하지 않는다.

## 4. 순차 생성과 재개 관리

- **내장 `image_gen` 도구로 이미지당 한 번씩 호출**한다. 여러 단어를 한 장의 묶음 이미지로 대신하지 않는다. 별도 API 키나 유료 API로 자동 전환하지 않는다.
- 시범에서 승인된 이미지는 재사용한다. 나머지는 **A1 → A2 → B1 → B2**, 각 수준에서는 기존 교재 순서로 진행한다.
- 10개 항목마다 진행 상황을 저장한다. 이 단위는 작업 체크포인트이며 앱의 일일 AI 제한을 추가하는 것이 아니다.
- 연결 목록에는 항목 ID·기본 뜻·교재 지문·장면·프롬프트 버전·상태·파일명·이미지 해시·실제 크기·검수 결과를 기록한다.
- 상태는 `대기/생성 중/생성됨/승인/보류/실패`로 구분한다. 승인된 항목은 재개 시 건너뛴다.
- 품질 미달은 문제를 특정해 **한 번 수정 생성**한다. 다시 미달이면 보류하고 원인을 기록한다. 한도·서비스 오류가 발생하면 호출을 중단하고 완료 파일을 보존한다.
- 중단된 호출은 결과 파일의 존재를 먼저 확인한다. 결과가 불명확한 호출을 자동으로 다시 실행하지 않는다.
- 수천 번의 호출이 필요한 장기 작업으로 관리한다. 전체 무료 생성 가능 여부나 완료 날짜는 사전에 보장하지 않는다.

## 5. 검수와 완료 기준

- 모든 이미지를 실제로 열어 **기본 뜻·품사와의 일치, 글자 부재, 스타일 일관성, 장면 이해 가능성, 작은 화면에서의 식별성**을 검사한다.
- `about`, `bank`, `light`, `record`처럼 다른 뜻의 항목이 잘못 연결되지 않는지 별도로 확인한다.
- 기능어·추상어는 학습용 연상 단서로 검토한다. 이미지에서 특정 영단어 하나를 유일하게 추론할 수 있다고 보장하지 않는다. 잘못된 뜻을 유도하는 결과는 승인하지 않는다.
- 연결 목록의 **3,809개 ID 누락·중복**, 승인 파일의 존재·디코딩·해시·크기, 중단 후 재개와 완료 항목 중복 생성 방지를 검사한다.
- 생성 수·승인 수·보류 수·실패 수를 분리해 보고한다. **3,809개 모두 승인되었을 때만 전체 이미지 제작 완료**로 표시한다.
- 후속 화면 반영에는 승인된 이미지와 일치하는 기본 뜻만 전달한다. 사용자 수정 뜻에는 기본 이미지를 임의로 연결하지 않는다.
- 본 단계에서는 기존 학습 기록·친숙도·성적·백업·API·DB와 운영 사이트를 변경하지 않는다.

## 6. 시범 제작 당시 기록

- 내장 `image_gen`으로 시범 **20장 / 20회 호출**을 완료했다. 수정 생성·자동 재시도·별도 이미지 API 전환은 없었다.
- [이미지 연결 목록](../data/word-image-manifest.json)에 3,809개 교재 ID와 기본 뜻·품사·교재 지문을 기록했다. 생성된 20장은 `generated`, 나머지 3,789개는 `waiting`이다. 사용자 승인된 항목은 아직 0개다.
- 모든 원본을 주 작업 폴더의 `outputs/oxford-images/14552b36a1653f2aed9e14b09c833c0031b1204de5e0bdfc6902543a05d4ba6e/`에 복사했다. 기본 생성 위치의 원본도 유지했다.
- 20장 모두 1,086 × 1,448 PNG다. 디코딩·파일 해시·프롬프트 해시·항목 연결과 완료 항목 재생성 차단을 확인했다. 로컬 Chromium 320px 미리보기의 로드·비율을 확인하고 20장 모두 실제 축소 화면을 열어 검토했다. 실제 iPhone 검사는 수행하지 않았다.
- `about` 부사와 `record` 명사는 의미 전달이 약한 후보다. 관사·접속사·조동사는 특정 용법을 떠올리는 연상 단서로 검토하며, 그림만으로 영어 용법이나 정답을 확정하지 않는다.
- 상세 결과·검토 메모·재개 절차는 [시범 검토 기록](OXFORD_WORD_IMAGES_PILOT.md)에 보존했다. 이 절의 수치는 사용자 스타일 유지 지시를 받기 전 시범 단계의 역사적 기록이다.

## 7. 전체 제작 승인과 현재 체크포인트

- 사용자 지시 **“지금과 같은 생성 방식을 유지하여 나머지도 진행해라.”**에 따라 시범 스타일과 내장 도구를 유지하여 나머지 제작을 시작했다. 전체 목표는 계속 3,809개다.
- 이 지시는 개별 이미지의 영어 의미까지 일괄 승인한 것으로 해석하지 않는다. 연결 목록의 `approved`는 원본·320px 화면을 대조한 **제작자 품질 검수 통과** 상태다. 독립 학습자 평가·사용자의 항목별 의미 승인과 구분한다.
- 추가 180개 항목을 제작했다. 현재 누적 200개 항목·210회 실제 호출이며, 10회는 `activity`·`about` 부사·`record` 명사·`boring`·`capital` 명사·`change` 동사·`close` 동사·`club`·`company`·`complete` 동사의 결함 수정이다. 모든 시도별 원본은 보존했다.
- `record` 명사는 이전 거리와 새 착지를 비교하도록 보완했다. `about` 부사는 한 번 수정 후에도 의미 전달이 약해 `held`로 남긴다. 해결된 것으로 표시하거나 추가 호출하지 않는다.
- `company`는 모니터 하단의 상표형 표식을 한 번 제거하려 했으나 v2에도 남아 글자·로고 금지 조건 미충족으로 보류했다. 두 시도 모두 보존하고 세 번째 호출은 하지 않는다. `complete` 동사는 마지막 조각과 빈자리의 외곽선을 맞춰 v2를 검수 통과했다.
- `capital` 형용사 ‘대문자의’는 글자 없는 키보드 후보가 일반 타이핑과 구분되지 않아 첫 시도 후 보류했다. 이 항목만 `A / a` 형태 비교를 허용할지 2026-10-06 사용자에게 물었으며 답변은 아직 받지 않았다. 글자 금지 조건을 유지하고 수정 1회를 남겨 둔다. 해당 보류도 3,809개 전체 완료에 필요한 미완료 범위이며, 시간 경과를 예외 승인으로 해석하지 않는다.
- 단계별 검수·저장 위치·중단 보호·재개 명령은 [진행 기록](OXFORD_WORD_IMAGES_PROGRESS.md)에 정리한다. 이 단계에서는 앱·운영 사이트·학습 기록을 변경하지 않는다.
