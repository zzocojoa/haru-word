## 1. 목표와 확정 범위

- 현재 교재의 **3,809개 학습 항목에 이미지 한 장씩** 제작한다. 같은 철자라도 품사·수준·기본 뜻이 다른 항목은 구분한다.

- **20장 시범 제작 → 사용자 확인 → 전체 순차 제작·검수** 순서로 진행한다.
- 이번 범위는 이미지와 연결 목록의 준비까지다. 첨부한 두 화면의 코드 수정, 이미지 호스팅과 운영 배포는 후속 작업으로 분리한다.

- 생성 이미지는 기본 생성 위치에서 주 작업 폴더의 **`outputs/oxford-images/<교재해시>/`**로 복사한다. Git 제외 폴더에 원본과 시도별 파일을 보존하며, 기존 파일을 덮어쓰지 않는다.

계획 확정 당시에는 계획 모드로 브랜치 생성·파일 저장·이미지 호출을 실행하지 않았다. 최초 문서 저장 요청에서는 새 브랜치와 계획 문서만 준비했다. 이후 사용자의 “다음 단계 진행” 요청으로 아래 시범 20장 제작을 진행했다.

## 3. 제작 기준과 시범 20장

- 단어 ID, 품사, 수준, 기본 뜻을 기준으로 장면을 작성한다. 기존 표현·예문은 의미 확인에 사용하며, 철자만 보고 장면을 정하지 않는다.
- 공통 스타일은 단순한 형태, 절제된 색, 깨끗한 배경, 세로형 구도로 고정한다. 어린이·교실·장식 소품을 기본 요소로 추가하지 않는다.
- 구체적인 단어는 사물이나 행동을 중심으로 표현한다. 기능어·추상어는 한 이미지 안에 **최대 두 개의 관계·대비 장면**을 허용한다.
- 시범 항목은 다음 20개로 고정한다.
  - 기본 6개: `apple`, `bicycle`, `climb` 동사, `bridge`, `careful`, `group`.
  - 뜻 구분 8개: `about` 전치사/부사, `bank` 은행/강둑, `light` 밝은/가벼운, `record` 기록/녹음하다.
  - 기능·추상 6개: `under`, `because`, `a, an`, `the`, `would`, `freedom`.
- 첫 `apple` 이미지로 스타일 기준을 만들고 나머지 이미지에 참고 자료로 전달한다. 시범 이미지는 채팅 안에 직접 표시해 확인받는다.
- 시범 검수 결과와 사용자 피드백을 계획 문서에 반영한 뒤 전체 제작 기준을 고정한다. 사용자 확인 전에는 나머지 항목을 생성하지 않는다.

## 4. 순차 생성과 재개 관리

- **내장 `image_gen` 도구로 이미지당 한 번씩 호출**한다. 여러 단어를 한 장의 묶음 이미지로 대신하지 않는다. 별도 API 키나 유료 API로 자동 전환하지 않는다.
- 시범에서 승인된 이미지는 재사용한다. 나머지는 **A1 → A2 → B1 → B2**, 각 수준에서는 기존 교재 순서로 진행한다.
- 10개 항목마다 진행 상황을 저장한다. 이 단위는 작업 체크포인트이며 앱의 일일 AI 제한을 추가하는 것이 아니다.
- 연결 목록에는 항목 ID·기본 뜻·교재 지문·장면·프롬프트 버전·상태·파일명·이미지 해시·실제 크기·검수 결과를 기록한다.
- 상태는 `대기/생성 중/생성됨/승인/보류/실패`로 구분한다. 승인된 항목은 재개 시 건너뛴다. 사용자가 제작 조건과 뜻의 충돌로 명시적으로 보류한 항목은 `policyHold`로 기록하고 생성·수정·승인을 차단한다. 생성 전 보류는 제작 수·호출 수에 포함하지 않으며 같은 결정을 다시 기록해도 원장·기존 시도는 바뀌지 않는다.
- 품질 미달은 문제를 특정해 **한 번 수정 생성**한다. 다시 미달이면 보류하고 원인을 기록한다. 한도·서비스 오류가 발생하면 호출을 중단하고 완료 파일을 보존한다.
- 중단된 호출은 결과 파일의 존재를 먼저 확인한다. 결과가 불명확한 호출을 자동으로 다시 실행하지 않는다.
- 수천 번의 호출이 필요한 장기 작업으로 관리한다. 전체 무료 생성 가능 여부나 완료 날짜는 사전에 보장하지 않는다.

## 5. 검수와 완료 기준

- 모든 이미지를 실제로 열어 **기본 뜻·품사와의 일치, 글자 부재, 스타일 일관성, 장면 이해 가능성, 작은 화면에서의 식별성**을 검사한다.
- `about`, `bank`, `light`, `record`처럼 다른 뜻의 항목이 잘못 연결되지 않는지 별도로 확인한다.
- 기능어·추상어는 학습용 연상 단서로 검토한다. 이미지에서 특정 영단어 하나를 유일하게 추론할 수 있다고 보장하지 않는다. 잘못된 뜻을 유도하는 결과는 승인하지 않는다.
- 연결 목록의 **3,809개 ID 누락·중복**, 승인 파일의 존재·디코딩·해시·크기, 중단 후 재개와 완료 항목 중복 생성 방지를 검사한다.
- 생성 수·승인 수·보류 수·실패 수를 분리해 보고한다. **3,809개 모두 승인되었을 때만 전체 이미지 제작 완료**로 표시한다.
- 후속 화면 반영에는 승인된 이미지와 일치하는 기본 뜻만 전달한다. 사용자 수정 뜻에는 기본 이미지를 임의로 연결하지 않는다.
- 본 단계에서는 기존 학습 기록·친숙도·성적·백업·API·DB와 운영 사이트를 변경하지 않는다.

- 내장 `image_gen`으로 시범 **20장 / 20회 호출**을 완료했다. 수정 생성·자동 재시도·별도 이미지 API 전환은 없었다.

- 모든 원본을 주 작업 폴더의 `outputs/oxford-images/14552b36a1653f2aed9e14b09c833c0031b1204de5e0bdfc6902543a05d4ba6e/`에 복사했다. 기본 생성 위치의 원본도 유지했다.

- `about` 부사와 `record` 명사는 의미 전달이 약한 후보다. 관사·접속사·조동사는 특정 용법을 떠올리는 연상 단서로 검토하며, 그림만으로 영어 용법이나 정답을 확정하지 않는다.
- 상세 결과·검토 메모·재개 절차는 [시범 검토 기록](OXFORD_WORD_IMAGES_PILOT.md)에 보존했다. 이 절의 수치는 사용자 스타일 유지 지시를 받기 전 시범 단계의 역사적 기록이다.

## 7. 전체 제작 승인과 현재 체크포인트

- 사용자 지시 **“지금과 같은 생성 방식을 유지하여 나머지도 진행해라.”**에 따라 시범 스타일과 내장 도구를 유지하여 나머지 제작을 시작했다. 전체 목표는 계속 3,809개다.
- 이 지시는 개별 이미지의 영어 의미까지 일괄 승인한 것으로 해석하지 않는다. 연결 목록의 `approved`는 원본·320px 화면을 대조한 **제작자 품질 검수 통과** 상태다. 독립 학습자 평가·사용자의 항목별 의미 승인과 구분한다.
- 추가 609개 항목을 제작했다. 현재 누적 629개 항목·655회 실제 호출이며, 26회는 `activity`·`about` 부사·`record` 명사·`boring`·`capital` 명사·`change` 동사·`close` 동사·`club`·`company`·`complete` 동사·`detail`·`DVD`·`email` 명사·`ever`·`exciting`·`fast` 부사·`few` 대명사·`friendly`·`goodbye` 감탄사·`keep` 동사·`match` 명사·`message` 명사·`million` 수사·`music` 명사·`neighborhood` 명사·`next` 형용사의 결함 수정이다. 모든 시도별 원본은 보존했다.
- `record` 명사는 이전 거리와 새 착지를 비교하도록 보완했다. `about` 부사는 한 번 수정 후에도 의미 전달이 약해 `held`로 남긴다. 해결된 것으로 표시하거나 추가 호출하지 않는다.
- `company`는 모니터 하단의 상표형 표식을 한 번 제거하려 했으나 v2에도 남아 글자·로고 금지 조건 미충족으로 보류했다. 두 시도 모두 보존하고 세 번째 호출은 하지 않는다. `complete` 동사는 마지막 조각과 빈자리의 외곽선을 맞춰 v2를 검수 통과했다.
- `exciting`의 프리즘 실험은 한 번 수정 후에도 빨강 띠가 출사면에서 위로 향하는 부분이 남아 의미 적합성을 보류했다. 원본·수정본·320px 검수 근거를 보존하고 세 번째 호출은 하지 않는다. 이 보류도 전체 완료에 필요한 미완료 범위다.
- `fast` 부사는 한 번 수정 후에도 두 주자의 전진 위치가 나란히 보이지 않아 교재 표현 `as fast as Mary`의 관계 단서가 부족하다. 정지 그림의 위치 차이를 실제 속도 차이로 단정하지 않으며 의미 적합성을 보류했다. v1/v2·320px 근거를 보존하고 세 번째 호출은 하지 않는다.
- `few` 대명사는 첫 그림에서 의자가 열두 개 대신 열 개여서 한 번 수정했다. v2의 열두 의자·남은 사람 한 명·빈자리 열한 개를 원본과 320px에서 각각 세어 검수 통과했으며 두 시도를 보존했다.
- `friendly`는 열린 문의 손잡이와 경첩 블록을 같은 자유 모서리에 그린 결함을 한 번 수정했다. v2의 바깥 경첩 블록 제거·문틀 쪽 부착 모서리와 손잡이의 관계·두 인물과 상자 두 개를 원본/320px에서 확인하고 통과했다. 실제 경첩은 가려져 있으며 v1/v2와 각각의 축소 근거를 보존했다.
- `goodbye` 감탄사는 열린 문의 손잡이/래치를 부착 모서리에 그린 결함을 한 번 수정했다. v2의 잘못된 왼쪽 부품·오른쪽 문틀 블록 제거/나무결 복원·두 인물의 작별 동작/가방을 원본과 320px에서 확인하고 통과했다. 실제 손잡이/경첩은 가려져 있으며 v1/v2·각 축소 근거를 보존했다.
- `keep` 동사는 위의 세 권/아래의 네 권으로 책 수가 달라 아래 추가 파란 책 한 권만 한 번 제거했다. v2의 위 두 권+손의 한 권·아래 세 권/두 방의 정돈 상태를 원본과 320px에서 확인해 통과했다. v1/v2·각 축소 근거를 보존했다.
- `match` 명사는 앞 선수 두 신발의 진한 상표 유사 곡선 장식을 한 번 제거했다. 특정 상표명을 단정하지 않는다. v2의 무지 밝은 갑피/물리적 칼라·끈·밑창과 선수 2명/라켓 2개/공 1개를 원본과 320px에서 확인해 통과했고 v1/v2·첫 보류 메모·각 축소 근거를 보존했다.
- `message`는 왼쪽 경첩 부착 모서리의 잘못 놓인 둥근 손잡이/받침만 한 번 제거했다. `million`은 계수기 더미의 흰 숫자 유사 표시창/인쇄 표식만 한 번 제거했다. v2의 문 구조/봉투 교환과 무지 나무 면/반복 손짓을 원본·320px에서 확인해 통과했고 두 항목의 v1/v2·첫 보류 메모·각 축소 근거를 보존했다. `million`은 교재 `a million times`의 과장 용법을 연상하며 정확한 백만 개를 그렸다고 표시하지 않는다.
- `music`은 기타 머리 오른쪽 끝의 글자/상표 유사 곡선 장식만 한 번 제거했다. v2에서 무지 갈색 나무 면과 기존 조율 부품/현/프렛·두 사람의 연주/청취 관계를 원본·320px에서 확인해 통과했다. 특정 회사/문자를 판독한 것으로 단정하지 않으며 v1/v2·첫 보류 메모·각 축소 근거를 보존했다.
- `neighborhood`는 왼쪽 아이의 올린 손에서 집 쪽으로 향하던 줄과 빨간 연에서 머리 왼쪽으로 내려가던 별도 줄을 한 번 수정했다. v2에서 손과 빨간 연의 연속 연결·집 4채/아이 2명/연 2개·오른쪽 연/줄을 원본·320px에서 확인해 통과했다. 왼쪽 손/팔 위치도 조금 바뀌었으므로 포즈가 픽셀 그대로 유지됐다고 표시하지 않는다. v1/v2·첫 보류·각 축소·기존 원본의 브라우저 부분 검사 근거를 보존했다.
- `next` 형용사는 오른쪽 다음 해 계획판의 마지막 두 칸을 가리던 파란 책을 한 번 축소/이동했다. v2의 판 아래 분리된 책 1권·왼쪽/오른쪽 각 3줄/줄별 4칸(열두 칸씩)·왼쪽 클립을 원본·320px에서 직접 확인해 통과했다. v1/v2·첫 보류·각 기본 생성 원본/축소 검사 근거를 보존하며 실제 날짜/중국어 학습 의도를 표시하지 않는다.
- 2026-10-06 사용자가 **“글자 금지 유지·두 항목 보류”**를 선택했다. `capital` 형용사 ‘대문자의’는 의미 전달이 약한 기존 키보드 후보·첫 시도·검토 기록을 보존하고 조건 보류를 추가했다. 수정 호출은 사용하지 않았고 현재 지시하에서는 새 생성·수정·승인으로 넘기지 않는다. `letter` 명사 ‘글자’는 문자 자체가 필요하므로 **생성 전에 보류**했다. 시도·이미지·검수 승인·호출을 만들지 않으며 편지나 무지 블록을 정답 그림으로 대체하지 않는다. 두 항목에 `policyHold`로 실제 사용자 지시와 생성 전/후 상태를 기록한다. 글자 예외를 허용하지 않으며 두 보류는 전체 3,809개 완료에 필요한 미완료 범위다.
