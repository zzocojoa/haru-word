## 3. 제작 기준과 시범 20장

- 단어 ID, 품사, 수준, 기본 뜻을 기준으로 장면을 작성한다. 기존 표현·예문은 의미 확인에 사용하며, 철자만 보고 장면을 정하지 않는다.
- 공통 스타일은 단순한 형태, 절제된 색, 깨끗한 배경, 세로형 구도로 고정한다. 어린이·교실·장식 소품을 기본 요소로 추가하지 않는다.
- 구체적인 단어는 사물이나 행동을 중심으로 표현한다. 기능어·추상어는 한 이미지 안에 **최대 두 개의 관계·대비 장면**을 허용한다.
- 시범 항목은 다음 20개로 고정한다.
  - 기본 6개: `apple`, `bicycle`, `climb` 동사, `bridge`, `careful`, `group`.
  - 뜻 구분 8개: `about` 전치사/부사, `bank` 은행/강둑, `light` 밝은/가벼운, `record` 기록/녹음하다.
  - 기능·추상 6개: `under`, `because`, `a, an`, `the`, `would`, `freedom`.
- 첫 `apple` 이미지로 스타일 기준을 만들고 나머지 이미지에 참고 자료로 전달한다. 시범 이미지는 채팅 안에 직접 표시해 확인받는다.
- 시범 검수 결과와 사용자 피드백을 계획 문서에 반영한 뒤 전체 제작 기준을 고정한다. 사용자 확인 전에는 나머지 항목을 생성하지 않는다.

## 4. 순차 생성과 재개 관리

- **내장 `image_gen` 도구로 이미지당 한 번씩 호출**한다. 여러 단어를 한 장의 묶음 이미지로 대신하지 않는다. 별도 API 키나 유료 API로 자동 전환하지 않는다.
- 시범에서 승인된 이미지는 재사용한다. 나머지는 **A1 → A2 → B1 → B2**, 각 수준에서는 기존 교재 순서로 진행한다.
- 10개 항목마다 진행 상황을 저장한다. 이 단위는 작업 체크포인트이며 앱의 일일 AI 제한을 추가하는 것이 아니다.
- 연결 목록에는 항목 ID·기본 뜻·교재 지문·장면·프롬프트 버전·상태·파일명·이미지 해시·실제 크기·검수 결과를 기록한다.
- 상태는 `대기/생성 중/생성됨/승인/보류/실패`로 구분한다. 승인된 항목은 재개 시 건너뛴다. 사용자가 제작 조건과 뜻의 충돌로 명시적으로 보류한 항목은 `policyHold`로 기록하고 생성·수정·승인을 차단한다. 생성 전 보류는 제작 수·호출 수에 포함하지 않으며 같은 결정을 다시 기록해도 원장·기존 시도는 바뀌지 않는다.
- 품질 미달은 문제를 특정해 **한 번 수정 생성**한다. 다시 미달이면 보류하고 원인을 기록한다. 한도·서비스 오류가 발생하면 호출을 중단하고 완료 파일을 보존한다.
- 중단된 호출은 결과 파일의 존재를 먼저 확인한다. 결과가 불명확한 호출을 자동으로 다시 실행하지 않는다.
- 수천 번의 호출이 필요한 장기 작업으로 관리한다. 전체 무료 생성 가능 여부나 완료 날짜는 사전에 보장하지 않는다.

## 5. 검수와 완료 기준

- 모든 이미지를 실제로 열어 **기본 뜻·품사와의 일치, 글자 부재, 스타일 일관성, 장면 이해 가능성, 작은 화면에서의 식별성**을 검사한다.
- `about`, `bank`, `light`, `record`처럼 다른 뜻의 항목이 잘못 연결되지 않는지 별도로 확인한다.
- 기능어·추상어는 학습용 연상 단서로 검토한다. 이미지에서 특정 영단어 하나를 유일하게 추론할 수 있다고 보장하지 않는다. 잘못된 뜻을 유도하는 결과는 승인하지 않는다.
- 연결 목록의 **3,809개 ID 누락·중복**, 승인 파일의 존재·디코딩·해시·크기, 중단 후 재개와 완료 항목 중복 생성 방지를 검사한다.
- 생성 수·승인 수·보류 수·실패 수를 분리해 보고한다. **3,809개 모두 승인되었을 때만 전체 이미지 제작 완료**로 표시한다.
- 후속 화면 반영에는 승인된 이미지와 일치하는 기본 뜻만 전달한다. 사용자 수정 뜻에는 기본 이미지를 임의로 연결하지 않는다.
- 본 단계에서는 기존 학습 기록·친숙도·성적·백업·API·DB와 운영 사이트를 변경하지 않는다.
