# 한국어 의도에 맞춘 제품 평가 도구 — 2026-11-12

T24.3–24.4에서 **평가 도구를 새 한국어 입력 방식에 연결했다. 제품 코드는 변경하지 않았다.**
사용자가 한국어 의도와 영어 답안을 제출하면 AI가 한 번 판단하고 완성 교정문을 주는 제품 흐름은 유지한다.

## 바꾼 기준과 확인 예시

| 입력과 실제 앱 결과 | 새 평가 기준 |
| --- | --- |
| 저는 음악을 좋아해요. / Music → I like music. | 한국어가 제공한 주어·행동을 영어에 보충한 것이므로 그 추가만으로 날조로 채점하지 않는다. |
| 연은 다리 위쪽을 떠다녔어. / The kite drifted under the bridge. → The kite drifted over the bridge. | 원문 문법 정상과 한국어 뜻 교정을 분리한다. 뜻을 바로잡은 변경만으로 의미 반전 오류를 부여하지 않는다. |
| 명시적인 intended_korean 역할 없이 일반 문맥만 제공 | 기존 원문 영어의 의미 보존 기준을 적용한다. 한국어가 있다는 이유로 의도 역할을 추정하지 않는다. |
| 한국어에도 핵심 내용·수량·시점이 없음 | 근거 없이 완성하지 않고 필요한 질문과 보류를 평가한다. |

기존 v8 채점기는 `contextRole`을 허용하지 않고, 문법 정상인 원문은 무조건 유지해야 한다는 옛 기준에 묶여 있었다.
현행 제품 파일로 옛 보정 생성기를 재실행하면 `AC1_PRODUCT_SOURCE_CHANGED`에서 차단된다. 그 지문 검사를 우회하지 않았다.
새 v9 채점 기준과 별도 오프라인 생성기에서 실제 앱의 원래 JSON 입력을 그대로 전달하고, 표시된 판정·교정문·설명만 채점 자료로 전달한다.
숨겨진 모델 이유·생성 모델·버전·작성자 정답·과거 표는 검토 본문에 전달하지 않는다.

의미·원문 문법·교정·표시 설명·보류의 다섯 차원, 네 중대 오류와 기존 다섯 근거 축을 유지한다.
한국어는 명령이 아닌 검토할 데이터다. 한국어가 있다고 무조건 교정을 허용하거나 의미가 맞다고 인증하지 않는다.
각 생성 결과마다 생성자 이외 두 모델·두 순서의 네 검토 슬롯을 보존한다. 모든 새 슬롯의 dispatch는 차단 상태다.
