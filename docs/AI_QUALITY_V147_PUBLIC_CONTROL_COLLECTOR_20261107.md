# 공개 참조 묶음 진단 수집기 · 2026-11-07

[이전 묶음 진단안](AI_QUALITY_V147_PUBLIC_CONTROL_BATCH_20261107.md)의 6개 실제 토큰 계산과 최대 6개 AI 응답을 연결하는 수집기를 구현했다. **새 유료 범위 승인은 대기 중이며 이번 실제 API·키 접근은 0이다.** 이전에 받은 실제 6응답·계산 2회·보수적 US$0.843789를 유지하고, 현재 세전 한도 US$5에 새 예산을 더하지 않는다.

## 동작과 중단 규칙

1. 고정 요청·공식 가격 기록·이전 비용 근거·실행 Node 버전과 소스 지문을 확인한다. 기존 V1 비용 원장 구현을 재사용하며 원래 예산 모듈 2개는 기존 관리 목록보다 오래되어 각각의 확인된 원본 지문으로 별도 고정했다.
2. 실제 진입점은 현재 사용자 승인과 새 범위의 승인 기록을 확인한 뒤에만 고정 실행 폴더를 사용한다. 승인 기록은 `.taskmaster/docs/ai-quality-v147-public-control-batch-authorization.json`이며, manifest에 해당 경로가 등록되어 있어야 한다. 현재 이 승인은 없다. 로컬 JSON 값만으로 사용자 동의를 대신할 수 없으며, 호출자는 실제 사용자 답변을 확인하고 공식 요금을 재확인해야 한다. 기존 키 재사용 결정은 다시 묻지 않는다.
3. 키를 읽기 전에 영구 `ONCE.json`을 한 번만 생성한다. 동시 프로세스나 재실행은 이 지점에서 중단한다. PID는 당시 기록이며 현재 살아 있다는 증거로 취급하지 않는다. 표식을 자동으로 지우거나 재시도하지 않는다.
4. 고정한 6개 계산 본문을 한 번씩 보낸다. 모델·지시문·입력·추론·전체 응답 스키마와 생성 본문의 지문을 연결하고 원문·영수증을 보존한다. 앞선 영수증이 바뀌거나 입력 하나라도 50,000토큰을 넘으면 모델 생성을 시작하지 않는다.
5. 6개 입력이 모두 확인되면 실제 입력 수로 원장을 만든다. 출력 4,096과 지역 처리 10% 여유를 유지하고, 첫 생성 전에 전체 6개 생성 슬롯의 비용을 예약한다. 각 요청 전에 소비 상태와 물리 파일을 다시 확인한다.
6. 응답을 받은 뒤 원문과 지문을 저장하고 사용량을 검사한다. 모델·요금 계층·입력 수가 다르거나 캐시 쓰기·초과 사용량이 나오면 최대 예약을 유지하며 중단한다. 비밀 값이 본문이나 헤더에 그대로 반사되면 원문을 저장하지 않고 안전한 상태·지문만 남긴다.
7. 정확한 사용량이 있으면 비용부터 정산한다. 미완성·거절·잘못된 출력 형식은 원문과 확인된 비용을 유지하고 품질 판정을 보류한다. 원장의 재정상 `completed`는 영어 품질 통과를 뜻하지 않는다.
8. 전체 응답이 있으면 36개 문항 판정·6개 공통 기준 판정을 별도로 검사한다. 불일치와 누락을 분모에서 제외하지 않는다. 35/36의 결과를 다수결로 통과시키거나 유리한 재요청을 하지 않는다. 이 진단은 통과해도 역할 자격·영어 정답·원래 12기준·출시를 승인하지 않는다.

프로세스가 중간에 죽으면 읽기 전용 검사기로 원장과 캡처를 확인할 수 있다. 종료 보고서가 없어도 영구 표식과 부분 비용을 관찰하며, 실제 전송 횟수를 파일만으로 확정하지 않는다. 읽기 검사가 잠금을 지우거나 원장을 수정하거나 재전송하지 않는다.

## 비용 범위

입력이 각각 50,000 이하일 때의 조건부 예약은 이전과 같은 **US$0.843789 + 생성 최대 US$2.015728 + 계산료 여유 US$2.015728 = US$4.875245 / US$5**다. 입력 수를 확인할 수 없으면 남은 캠페인 예산을 전부 보류한다. 계산 API의 별도 단가와 청구서는 미확인이며, 계산료 여유는 청구액 보증이 아니다. 제품의 출력 한도·임의 일일 호출 제한·결제 설정은 바꾸지 않는다.

검사에서 사용하는 20,000 입력·1,000 출력은 **가상 사용량**이다. 이 가정의 생성 비용 US$0.715000과 캠페인 총액 US$3.574517은 수집기 계산 검사값이며 실제 사용액이나 예상 견적이 아니다. 잘못된 답변의 사용량을 보존하는 검사도 이 가정의 비용과 미확정 최대 예약을 구분한다.
