## 2차: 공통 요청·단어장 첫 진입 개선

**로컬 판정: 이번 목표인 재접속·단어장 첫 진입 지연을 줄였다. 운영 배포는 하지 않았다.** 초기 JS 요청은 1차 31개 → 2차 15개다. 느린망 재접속은 1차보다 505–679ms(14.0–23.2%) 단축됐다. 운영 v133 빌드와도 같은 실행에서 비교했으며 느린망 재접속이 3개 기록 조건 모두 빨랐다. 기본망은 작은 차이나 표본 범위가 겹치는 조건이 있어 보편적인 개선율로 일반화하지 않는다.

### 구현과 유지 조건

- `build/learning-chunks.ts`는 클라이언트의 초기 **정적** 의존성만 묶는다. 동적 import는 경계 밖에 두고 Vinext의 기존 framework 그룹·entry 소유권을 유지한다. 작은 하위 그룹의 병합 기준은 32KiB이며 서버/RSC 빌드는 건드리지 않는다. 전체 예문/이미지 자료가 초기 그래프로 돌아오면 빌드를 거부한다.
- 단어 목록·검색은 기본 뜻과 3,380B 문법 도움말 목록만 사용한다. 가벼워진 `WordLibrary`는 초기 경로에 두어 목록 진입의 추가 모듈 대기를 없앴다. 편집기·개인 단어 입력·문법 본문은 실제로 열 때만 받는다. `app/library/grammar-workspace.tsx`는 방문 후 유지되어 초안·목록 펼침·학습 위치가 탭 이동으로 사라지지 않는다.
- `deferredView`는 모듈 요청/완료 컴포넌트를 공유하고 준비되면 표시한다. 로딩·실패 중 편집창의 접근성 제목을 유지하며, 닫힌 화면의 늦은 응답은 상태를 변경하지 않는다. 명시적 캐시 복구와 저장/미저장/복원·이탈 보호는 유지했다. 생성된 `~` 포함 정적 JS 파일명도 안전한 재조회 대상이다.
- `data/grammar-index.json`은 원본의 15개 ID·품사·제목·역할·첫 예문을 그대로 생성한다. 교재 변경 후 `node --experimental-strip-types scripts/prepare-grammar-index.mjs`를 실행한다. 빌드의 `--check`가 바이트/원본 SHA를 검사한다. 단위 검사와 실제 built Worker 검사에서 초기 및 단어장 첫 진입에 전체 예문·이미지 목록·문법 교재를 받지 않는 것을 확인했다.

API·백업·revision 충돌·초안·첫 답·성적·한국 날짜·AI 제공자/실행 정책은 변경하지 않았다. 의존성 추가와 DB 마이그레이션은 없다. 결제 설정·운영 환경·운영 학습 기록·이미지 호스팅은 변경하지 않았다.
