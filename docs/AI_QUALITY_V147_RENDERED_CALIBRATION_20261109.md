# T34.3·T34.4 수정 화면을 사용하는 정식 보정 요청

[수정 화면 대조](AI_QUALITY_V147_RENDERED_PANEL_ACTUAL_20261109.md)에서 사전 기대값과 일치한 12개를 정식 보정 요청에 연결했다. 각 문항을 Sol·Terra·Astra에서 입력 우선과 피드백 우선으로 한 번씩 채점하는 기존 72개 개별 요청을 유지했다. 11개는 화면과 기존 문법·사전 출처 요약을 연결했고, 1개는 피드백이 없을 때 점수를 매기지 않는 통제다.

기존 요청에 들어갔던 내부 문법·목표 상태 대신 학습자가 보는 상태 문구, 교정문과 설명을 채점 입력으로 삼는다. 두 문제 문항의 교정문은 양쪽 모두 비어 있고 형태 오류와 교정 보류가 각각 표시된다. 요청마다 기존 문항·출처·모델·순서·출력 형식과 입력 계산 본문을 대조했다. 새 계획 지문은 `2c96bc43df962814774d6abadeec3c3df748658f69ad4325dbfbd98a391298a8`이다.

| 예약 검산 | 세전 US$ |
| --- | --- |
| 72개 계산료 여유 | 2.520000 |
| 요청당 입력을 1토큰으로 놓은 전체 예약 하한 | 4.278072 |
| 요청당 입력 상한 8,000토큰의 전체 예약 상한 | 8.567184 |
| 추가 예산 원장 가용액 | 3.039780 |
| 예약 하한과 가용액의 차이 | 1.238292 |

예약 하한은 입력 비용을 거의 제외하고 기존 출력 상한과 계산료 여유를 적용한 값이다. 실제 사용 토큰이나 청구액의 하한으로 해석하지 않는다. 분할 예약은 한 문항의 요청 6개를 시작할 수 있게 하지만 72개 전체의 정산이 현재 한도에 들어온다는 근거가 없다. 새 요청의 실제 토큰 계산과 모델 호출은 각각 0회다.

가상 응답으로 72개 중 하나가 중대 오류를 놓쳤을 때 71/72 및 해당 누락이 기록되는 것을 확인했다. 전체 요청을 준비한 상태이며 출처 자격 확정, 실제 정식 보정, 예비·확인 평가와 운영 게이트는 보류다. 이전 채점과 평가 원장은 보존했다.
