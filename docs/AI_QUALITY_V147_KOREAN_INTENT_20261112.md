# 단어 문장 만들기: 한국어 의도와 영어 답안 — 2026-11-12

사용자 요청에 따라 `ai-quality-v147`의 T5.2·T10.2·T15.2에 한국어 의도 입력을 반영했다. 단어 문장 만들기의 순서는 다음과 같다.

1. **의도한 한국어 문장**을 먼저 작성한다. 기존 문맥의 500자 한도를 사용한다.
2. 다음 칸에 목표 단어를 사용한 **내 영어 문장**을 작성한다.
3. 두 칸을 작성한 뒤 **AI 참고 의견 요청**을 누른다. 두 문장을 한 번의 요청에 함께 전달한다.

예시: 목표 단어 `over`, 한국어 ‘사람이 물 위에 걸어가고 있어.’, 영어 `A person walk over the water.`. 로컬 검증에서는 `A person is walking over the water.`라는 고정 AI 응답으로 표시·보관을 확인했다. 이 결과는 실제 모델의 새 답변이나 품질 점수가 아니다.

## 구현과 보관

- `app/study/sentence-stage.tsx`, `app/sentence-feedback.tsx`, `app/feedback-context-input.tsx`에서 한국어 → 영어 → 검사 순서로 보여 준다. 새 단어 AI 요청은 한국어·영어가 모두 있어야 실행된다. 기존 학습 완료·건너뛰기 흐름은 유지한다.
- `app/study/use-sentence-feedback.ts`도 빈 한국어로 새 요청을 보내지 않는다. 이미 발급된 요청의 결과 복구는 같은 UUID 조회로 이어갈 수 있다.
- 기존 `contextNote` 전송·보관과 계정 소유권을 확인하는 로컬 문맥 초안을 재사용한다. 검사 전 한국어는 기존 7일 기기 초안 정책을 따른다. AI 결과에는 요청 당시 한국어를 보관한다. 한국어를 바꾸면 지문도 바뀌어 이전 결과를 현재 조건의 제안으로 적용할 수 없다.
- 한국어는 학습자의 뜻·상황·시점·수량을 이해할 자료로 전달한다. 모델 지시문으로 취급하지 않는다. 일상 보완 메모를 자동 전송하지 않는다. 판정 지시문은 `reference-v9`, 저장 검증 버전은 기존 `judgment-v7`이다. 옛 결과를 새 결과로 다시 표시하거나 재채점하지 않는다.
- 새 DB 필드·SQL 마이그레이션·API 필드 추가는 없다. 과거 클라이언트의 선택적 문맥 API 형식과 저장 기록을 유지한다. 한국어를 작성하지 않은 과거 요청의 복구·조회도 차단하지 않는다.
