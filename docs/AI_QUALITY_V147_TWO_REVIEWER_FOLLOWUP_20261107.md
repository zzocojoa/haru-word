# 새 기준의 2모델 후속 공개 진단 — 실행 승인 전

목적은 보완한 판정 기준이 실제 모델 응답에 적용되는지 확인하는 것이다. 공개6문항을 Sol·Terra 각각 두 순서로 검토한다. **4응답·4실제 입력 토큰 계산·24판정·공유 기준4회**로 고정한다. Astra를 제외한 부분 진단이며 기존3모델 평가나 전체 개선 목표를 완료 처리하지 않는다.

이 문서는 새 실행안이다. 앞서 승인받은 공개6문항×3모델×2순서의6응답/6계산은 phase52에서 완료했고 원장을 닫았다. 그 승인과 원장을 재사용해 이번4회를 실행하지 않는다. 기존 키 재사용 결정은 이미 승인돼 추가 선택을 요구하지 않는다. 새 호출 범위만 사용자 확인을 기다린다.

## 비용과 중단 조건

총 한도는 기존 사용분을 포함한 **세전 US$5**다. 현재 보수적 총액 US$3.788335와 잔여 US$1.211665를 유지한다. 이전 계산료 여유와 미정 사용량의 최대 예약을 환급하거나 초기화하지 않는다.

| 항목 | 조건부 최대 USD |
| --- | ---: |
| 기존 보수적 비용·예약 | 3.788335 |
| 새4응답: 입력 각50,000 이하·출력 각4,096 이하 | 0.465168 |
| 새4계산에 별도로 남기는 비용 여유 | 0.465168 |
| 합계 | **4.718671** |
| 한도 대비 여유 | 0.281329 |

이는 모델 최대 컨텍스트를 실제 입력량으로 가정한 계산이 아니다. 50,000은 실행 전 중단 경계다. 승인 후 최종 요청의 instructions·input·reasoning·출력 schema까지 포함해 **네 요청 모두 먼저 계산**한다. 측정값으로 모델별 비용을 다시 산정하고 정수 마이크로달러 단위로 올림해 예약한다. 하나라도 경계를 넘거나 계산이 불확실하면 생성은 시작하지 않는다.

[OpenAI 공식 가격](https://developers.openai.com/api/docs/pricing)의 Standard 단가(입력/출력, 백만 토큰당)는 Sol US$2/10, Terra US$1/5다. 지역 처리 추가율10%도 보수적으로 적용한다. [토큰 계산](https://developers.openai.com/api/docs/guides/token-counting)과 [캐싱](https://developers.openai.com/api/docs/guides/prompt-caching)을 2026-11-07 확인했다. 캐싱은 명시 모드·breakpoint 없음으로 고정하고, 예기치 않은 캐시 사용/쓰기량은 보류한다.

**계산 API의 별도 단가와 청구서는 확인되지 않았다.** 새 계산 여유는 관리상 보수적 예약이며 실제 청구액의 상한을 보증하지 않는다. 계산료를 무료로 가정하지 않는다. 같은50,000/4,096 경계와 동일 여유 정책으로3모델·6응답을 반복하면 US$7.819791이므로 이번안으로 실행하지 않는다. 다른 Astra 설계까지 모두 불가능하다는 뜻은 아니다.

## 실행과 보존 규칙

1. 현재 사용자 새 범위 승인·고정 실행안/hash·US$5·기존 비용·이전 닫힌 원장의 bytes를 키 접근 전에 확인한다.
2. 새 고유 실행 ID와 영구 소유권 파일을 생성한다. 중단·오류·프로세스 종료 후 같은 실행을 다시 보내지 않는다.
3. 네 입력 계산 영수증을 실제 생성 요청 bytes에 연결한다. 네 비용 예약이 끝난 뒤 모델 요청을 순차 전송한다. 공식 Responses 경로만 사용한다.
4. 응답 원문·요청·전송 의도·사용량을 기록한다. 비밀 값이 포함된 응답은 원문을 남기지 않고 보류 사유만 기록한다.
5. 사용량이 확인되면 품질 검사 실패와 별도로 비용을 정산한다. 불명 사용량은 소비한 슬롯의 최대 예약을 유지한다. 원장은 종료하고 재개하지 않는다.
6. 새 기준 hash·항목 ID·구조 모순과 공개 대조 기대값을 검사한다. 불일치를 원문과 함께 보존하며, 기대값 수정·다수결 합격·자동 재시도를 하지 않는다. 읽기 전용 재검사는 전송하지 않는다.

응답별 공유 기준은 한 번만 세어 총4회다. 이를24개 문항의 독립 판정으로 부풀리지 않는다. 사전 기대값은 기존대로 보존하며 같은 개발 과정에서 작성된 미자격 기준이다. 새 본문과 항목 별칭도 기존 응답을 새 평가로 재활용할 수 없게 구분한다.

## 성공 조건과 해석 한계

- 도구 성공: 4개의 정확한 입력 계산과 최대4개의 응답을 한 번씩 수집하고, 요청/원문/영수증/원장 연결을 다시 확인할 수 있다.
- 진단 결과: 고정24판정의 일치·불일치, 공유 기준4회, 모델/순서별 결과와 구조 오류를 함께 보고한다. 24/24라도 영어 정확도나 평가자 자격으로 해석하지 않는다.
- 실제 효과: 기존 결과와 기술적으로 대조하되 공개·개발 노출 문항, 순서별 별칭, 단일 관측의 영향을 고려한다. 기준 보완의 인과 효과·새로운 문장으로의 일반화는 입증되지 않는다.

새 실행기는 `.taskmaster/scripts/ai-quality-v147-two-reviewer-collector-v1.mjs`, 고정안/계산/분석기는 `ai-quality-v147-two-reviewer-followup-v1.mjs`다. 기존 유료 수집기와 고정8원본·6응답·원점수10/36·사용량·닫힌 원장은 변경하지 않는다. 구6응답 검사기는 계속6개를 요구하고, 새4응답을 누락된 Astra 결과인 것처럼 채우지 않는다.

검증 원본은 ROOT `outputs/ai-quality-v147-implementation-20261106/phase55/`에 보관한다. 최종 검사·보존 결과는 그 폴더의 최종 검증 기록을 따른다. 실제 유료 전송·키 접근은 이번 준비 과정에서0이다. 제품547입력/407빌드와 이전 제품 검증은 그대로 보존하며 제품 전체 테스트·타입·빌드를 이번 도구 준비에서 다시 실행하지 않는다.

T34/자식4개는 review, 전체 품질·출시는 held다. 평가 방법·실행 도구 보완과 제품 문제 해결은 구분한다. 독립 AI 기준 자격, Astra, 새 참조/예비·확인 평가, 일반화, 학습 효과, 운영·출시·1일/7일 점검은 남아 있다. 커밋·푸시·PR·배포·운영 학습 기록 변경·미병합 산출물 삭제는 수행하지 않는다.
