# T34.3 추가 문맥 질문의 생성·저장·표시·평가 전달 검증

## 확인 결과와 이전 가정의 정정

**추가 질문이 평가 입력에서 누락된다는 문제는 이번 검사에서 발견되지 않았다.** `contextNeeded`는 모델 응답의 고정 종류이며, 앱이 검토한 한국어 질문으로 바꿔 `explanation`의 `추가 문맥:` 줄에 넣는다. `FeedbackDetail`은 이 설명을 `RecordText`로 표시하고, 평가 컴파일러도 설명 전체를 전달한다. 모델이 만든 자유 서술 이유는 이 표시 경로에서 사용하지 않는다.

phase60 문서의 “별도 UI의 contextNeeded 선택값·실제 추가 질문 위젯”이라는 표현으로 별도의 질문 표시 필드가 있고 그것을 놓쳤다고 해석하면 잘못이다. `FeedbackContextInput`은 학습자가 표현 형식과 문맥을 입력하는 기능이고, 피드백에 표시하는 질문은 설명문에 있다. 원래 모델의 enum을 평가자에게 별도 전송하지 않는 사실만으로 질문 누락이라고 판단하지 않는다. 당시 문서·준비 기록·동결 근거는 보존하고 이 후속 결과로 정정한다.

이번 변경은 발견되지 않은 누락을 가정하여 제품 필드나 평가 프로토콜을 늘리는 대신, 실제로 연결된 경로를 확인하는 재사용 회귀 검사다. 제품5차원/중대4개와 참조7차원/중대5개의 계약을 유지한다.

## 검증의 한계와 후속 조건

브라우저 검사는 실제 제품의 표시 컴포넌트를 사용했지만 전체 학습 화면에서 버튼을 눌러 생성·저장한 사용자 흐름은 아니다. Worker API의 합성 인증과 컴포넌트 렌더링을 연결한 로컬 검사이며, 운영 인증·실제 iPhone/VoiceOver를 검사하지 않았다. 긴 문서는 컴포넌트 전용 합성 입력이며 Worker가 생성한 추가 결과로 세지 않는다. T37의 설명 정확성·새 예문 적용성과 T38의 승인된 운영 합성 계정 확인은 완료되지 않았다.

질문이 전달되는 사실은 그 질문이 매 상황에 적절하다거나 AI 평가자가 정확히 이해한다는 증거가 아니다. 실제 영어 품질·참조/평가자 자격·독립 가족·위험/MDE/검정력/N/r·최종 본문과 실측 견적·확인/일반화·학습 효과·출시/1일/7일은 남는다. T34와34.3은 `review`를 유지한다.

제품547입력/407빌드파일·기존 요청/점수/원장/승인/실패 이력은 보존한다. 제품 코드나 런타임 평가 도구는 바꾸지 않았으므로 기존 제품 단위/타입/빌드를 다시 실행하지 않고 해시를 확인했다. 새 파일의 회귀·린트와 갱신된 관리/대시보드 검증을 구분해 기록한다. 기존 Site/DB 바인딩·SQL·lockfile·운영 게시·Git 작업·미병합 산출물 삭제는 없다.
