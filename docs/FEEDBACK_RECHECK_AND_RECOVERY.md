# 명시적 재점검과 교정 적용 보호

Task14.1 구현. AI 참고 의견이 이미 있거나 같은 문장이거나 판단 보류/과거 모델 의견이어도 사용자가 버튼을 누르면 다시 요청할 수 있다. 화면 진입·모델 변경·문장 편집·기록 조회·복원은 호출하지 않는다. 요청/저장 중과 빈 입력에서는 버튼을 잠근다.

AI가 검토한 문장과 현재 입력이 다르면 적용 버튼은 즉시 입력을 바꾸지 않고 비교 화면을 연다. 현재 입력과 적용할 제안을 확인한 뒤 별도 버튼으로 적용한다. 비교를 연 뒤 문장이나 AI 응답이 바뀌면 확인을 무효화하고 다시 비교해야 한다. 취소하면 현재 입력을 유지한다.

적용 전 문장을 메모리에 보관해 바로 되돌릴 수 있다. 적용 후 다시 편집했다면 자동 되돌리기를 막고 적용 전 문장을 확인/복사할 수 있게 한다. 적용/취소/되돌리기 뒤 키보드 초점도 이동한다. 공백만 다른 문장을 불필요하게 다시 쓰지 않는다. 문법 쓰기에서 입력 변경으로 저장 feedback이 해제되어도 현재 화면의 마지막 제안과 되돌리기를 유지한다. 학습 성적·첫 답·교재 진도는 이 조작에서 변경하지 않는다.

교정 적용 자체의 즉시 되돌리기는 현재 화면의 메모리 기능이다. 입력과 마지막 제안은 아래 Task14.2의 기기 보관으로 복구한다. 과거 모든 편집/되돌리기 이력을 서버에 추가 저장하지 않는다.

## 검증

```powershell
node --experimental-strip-types --test tests/feedback-correction.test.mjs tests/feedback-refactor.test.mjs tests/feedback-safety.test.mjs
node tests/feedback-correction-qa.cjs
```

React 상호작용 harness는 합성 문장만 사용하고 fetch를 가상 응답으로 대체한다. Chromium/WebKit에서 각각 13개 항목을 확인한다. 같은 문장/보류/과거 의견의 명시적 재요청, pending 잠금, 단어/문법 적용·되돌리기, 수정 전 제안 비교·취소·확인, 비교/적용 후 편집 보호, 새 응답에 의한 확인 무효화, 초점·공백 보존과 외부 요청 0을 검사한다. 이는 실제 빌드 Worker·운영 계정·실제 iPhone 검사가 아니다. 최종 앱/백업/두 기기 회귀는 Task14.2/15에서 수행한다.

## Task14.2의 보관/삭제 및 요청 복구 정책 — 로컬 구현 후보

다음 정책을 로컬 후보에 구현했다. 운영에는 아직 게시하지 않았다. 서버 영수증의 상세 계약과 배포/롤백은 [요청 영수증](FEEDBACK_REQUEST_RECEIPTS.md)을 따른다.

- 학습 초안은 로그인한 계정의 이 브라우저에만 보관한다. 새 서버 초안 테이블은 만들지 않는다. 마지막 편집 후 7일 동안 복구 대상으로 삼고, 만료한 데이터는 읽지 않으며 다음 접근 때 삭제한다. 로그아웃·계정 전환·사용자의 임시 입력 삭제에서도 제거한다. 브라우저가 닫힌 동안 즉시 물리 삭제된다고 보장하지 않는다.
- 단어는 기존 question 키(session/entry/stage/retry)별 편집 초안, 문법은 lesson/contentVersion/쓰기 단계의 편집 필드만 복구한다. 첫 답·성적·학습일·수업 완료·회상 성과를 초안으로 덮어쓰지 않는다. 입력을 다시 보여주는 것만으로 AI를 호출하거나 채점하지 않는다.
- 같은 질문의 두 탭 초안을 하나의 저장 키로 서로 덮지 않도록 탭별 변형을 유지한다. 서버 기준이 바뀌었거나 여러 변형이 있으면 자동 선택 대신 비교/선택으로 복구한다. 저장 성공은 현재 초안과 실제 승인된 snapshot이 일치할 때만 정리하며 오래된 저장 응답으로 새 초안을 지우지 않는다.
- 정상 종료/새로고침에서 해제한 페이지 표식만 이전 초안의 인계를 허용한다. 열린 탭·뒤로가기 캐시에 남은 페이지·강제 종료 여부가 불명인 페이지의 변형은 임의 삭제하지 않는다. 동일한 변형들은 화면에서 한 선택지로 묶는다. 강제 종료한 페이지의 중복 자료가 여러 개 남으면 20개 한도에 포함되며 사용자가 설정에서 정리할 수 있다.
- 계정 범위의 초안은 최대 20개·합계 1MiB, 단일 항목 64KiB로 제한한다. 한도·저장소 접근/용량 오류 때 미저장 초안을 임의 삭제하지 않고 현재 입력 유지와 백업/정리 안내를 제공한다. 개인정보는 로컬 평문으로 보관됨을 알리고 설정에서 삭제할 수 있게 한다. 문장·답변을 진단에 기록하지 않는다.
- 현재 화면의 마지막 AI 제안도 해당 초안의 복구 자료로 보관해, 새 입력 때문에 grammar.feedback을 해제한 경우의 비교 자료를 유지한다. 기존 서버 의견·원본 백업의 필드를 새 채점이나 임의 변환으로 고치지 않는다.
- 단일 AI 요청의 중복 과금/응답 유실 복구에는 계정+요청 UUID의 서버 영수증을 사용한다. D1 claim은 제공자 호출 전 원자 저장하고 동일 UUID를 다시 실행하지 않는다. 별도 상태 조회는 추가 AI 호출 없이 완료/처리 중/실패/불명 결과를 돌려준다. 동일 ID의 다른 입력·모델·목표는 충돌로 거절한다.
- 영수증의 응답 본문은 유효 24시간, 중복 실행 방지용 ID/지문/상태는 최대 7일로 두고 이후 접근에서 순차 정리한다. 만료/불명 요청을 자동 재전송하지 않는다. 새 유료 요청은 사용자 버튼으로 새 UUID를 만든 경우만 허용한다. 운영 집계 쓰기 실패는 의견 생성을 막지 않으며 안전한 코드만 기록한다.
- 새 D1 영수증 테이블이 필요하므로 migration/계정 소유권/정리·복원·배포 순서와 reader를 유지하는 롤백을 구현·검증한 뒤 운영에 적용한다. claim 저장이 실패하면 제공자를 호출하지 않는다. 완료 응답 저장이 실패하면 성공/복구 가능 여부를 구분하며 자동 재호출하지 않는다.
- CSV/tutor 전달에는 보류/유효/수정 전 상태를 표시한다. 보류한 제안/설명을 교정 정답처럼 보내지 않는다. JSON 원본 백업은 raw 의견과 legacy structure를 보존한다. CSV 수식 방어와 기존 열의 호환성도 유지한다.

검사에는 실패→브라우저 프로세스 종료→복구, 로그아웃/계정/탭 변경, 409와 최신 입력, 오래된 저장 응답, 중복 POST·응답 유실 후 조회, 통계/영수증 DB 실패, 만료·삭제·보류 export 및 전체/분할 백업의 원자성을 포함한다. 브라우저 상호작용 harness와 빌드 Worker 통합 검사를 구분해 기록한다. 현재 설치된 Windows WebKit은 한국어 경로의 persistent profile에서 단순 localStorage 값도 1초 뒤 사라졌으며, ASCII 임시 프로필에서는 재조회/재시작을 유지하는 최소 재현을 확인했다. harness는 ASCII 임시 프로필을 사용한다. 이는 실제 iPhone/Safari 검증이 아니다.

외부 SSO 화면에서 로그아웃하거나 브라우저가 저장소 접근을 거부하면 즉시 물리 삭제를 보장할 수 없다. 앱의 명시 로그아웃 경로는 기기 보관 삭제를 시도하며, 인증 불명401은 입력 유실을 피하기 위해 캐시를 숨기고 보존한다. 새 계정으로 확인된 페이지를 열면 이전 계정 캐시를 제거한다. 원본 JSON 백업은 학습 기록만 포함하고 임시 초안·영수증은 포함하지 않는다.
