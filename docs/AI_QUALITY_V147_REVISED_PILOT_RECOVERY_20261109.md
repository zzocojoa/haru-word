# T26.3 앱 중단 후 요청 결과 복구

동결한 기준판과 후보판을 각각 격리된 로컬 Worker에서 실행했다. 각 앱에서 완료 기록 하나와 합성 응답이 잘린 실패 기록 하나를 먼저 저장했다. 세 번째 요청에서는 앱이 요청 ID를 저장하고 가상 AI 호출에 진입한 순간, 응답을 반환하기 전에 해당 테스트 프로세스를 강제 종료했다. 단어 요청은 기준판에서, 문법 요청은 후보판에서 이 상태를 만들었다.

| 재시작 후 확인 범위 | 결과 |
| --- | --- |
| 완료·실패 기록 재조회 및 동일 요청 재제출 | 완료 2건과 실패 2건의 저장된 응답을 그대로 반환 |
| 응답 반환 전 중단된 요청 | 2건 모두 재시작 직후 처리 대기, 실제 2분 대기 시간 이후 결과 미확인 |
| 같은 요청 ID 재제출 | 재시작 후 가상 AI 호출 0회 |
| 계정 분리와 데이터 보존 | 다른 계정 조회 차단, 학습 상태와 요청 기록 일치 |

재시작 전 저장소 파일 사본과 스키마 지문을 보존했다. 종료한 프로세스의 신원과 부재를 확인한 뒤 같은 로컬 DB를 다시 열었다. 독립 Python 검사에서 두 DB의 사본 18개와 최종 실행 종료 기록을 대조했다. 앱 영수증 단위 검사는 Node 22와 24에서 각각 11/11, 사용자 화면의 복구 요청 로직 검사는 Node 24에서 11/11 통과했다.

실제 평가에서는 결과 미확인 요청을 미측정으로 남기고 같은 요청을 재전송하지 않는다. 이번 검증은 가상 응답을 사용한 로컬 앱의 중단·복구다. 실제 AI 호출·토큰 계산·키 읽기는 0회이며 정식 예비평가는 보류다. 실행 결과와 이전 DB 사본 위치는 Git 제외 `outputs/ai-quality-v147-implementation-20261106/phase140/`에 기록했다. [전체 로컬 재현 기록](AI_QUALITY_V147_REVISED_PILOT_REHEARSAL_20261109.md)
