# T34.3 — 제품 피드백 판정 기준 연결과 범위 정정

2026-11-08 · `ai-quality-v147` · phase60. 제품용 판정 기준 초안을 모의 토큰 사전 확인·수집·캡처·보정·보고·복구에 연결하는 작업이다. 실제 영어 품질, 평가자 자격, 위험 허용치, 최종 표본이나 출시를 승인/검증한 결과가 아니다. 전체40개/세부133개 목표를 유지한다.

## 먼저 정정하는 가정

**참조 레코드의7개 차원/중대5개와 제품 피드백의5개 차원/중대4개는 서로 다른 검토 계약이다.** 기존 `reference-operational-rubric-v1.json`은 scope에 reference-record review라고 명시한다. 제품의 `decision-contract-v4.json`은 meaning/grammar/correction/explanation/abstention을 별도로 정의한다. 항목 수가 다르다는 이유만으로 제품 본평가를7개 차원으로 바꿀 근거는 없다.

phase59의 `sevenDimensionMainEvaluationFrozen:false`, `familyNewSevenDimensionMainFrozen:false` 및 “새7차원 본평가 스키마가 필요하다”는 후속 요구 가정은 이 문서와 phase60 `scope-correction.json`으로 정정한다. 당시 기록·지문·결과는 보존한다. 가족 단위 분모·혼합 악화·미측정·무결성 관련 phase59 근거 자체는 유효하며 삭제하지 않는다. 서로 다른 역할을 구분하는 것이지 실제 품질 검증 범위를 줄이는 것이 아니다.

## 실제로 보완한 내용

제품용 운영 기준은 `.taskmaster/docs/ai-quality-v147-product-operational-rubric-v1.json`에 새 버전으로 작성했다. 기존5개 차원/중대4개와 원래 의미를 유지하면서 성공/실패/불확실/미측정의 뜻, 차원 사이의 경계와 중대 위험의 구조적 일관성을 명시한다. 참조용7개 기준·기대값·과거 응답과 점수는 변경하지 않는다.

| 제품 평가 항목 | 판단 대상과 경계 |
| --- | --- |
| meaning | 원문에서 요청한 단어/품사/뜻 또는 문법 기능의 사용을 제품이 올바르게 판단했는지. 단어 존재만으로 정답 처리하지 않고, 목표 라벨 차이를 문법 오류와 섞지 않음 |
| grammar | 원문 문법 판단의 타당성. 교정안의 의미 동등성·전송 오류·목표 라벨과 분리하고, 참조가 허용한 라벨 차이만으로 영어 오류를 만들지 않음 |
| correction | 원래 자연스러운 문장의 보존, 최소 교정과 의미 보존, 안전한 교정 보류. 부정·참여자·시간·수량·사건·화행을 보호함 |
| explanation | 학습자가 실제 보는 설명의 사실·규칙·수정 비교. 앱이 작성한 문구와 숨겨진 모델 이유를 혼동하거나, 교정이 맞다는 이유로 잘못된 설명을 통과시키지 않음 |
| abstention | 필요한 불확실성의 보존과 구체적인 추가 맥락 질문. 독립적으로 판단 가능한 문법/목표 사용은 보존하고, 전송 실패를 책임 있는 보류로 세지 않음 |

중대 위험은 기존 approveBadGrammar/reverseMeaning/swapRoles/inventedIntent다. 예컨대 swapRoles=true라면서 correction=pass인 응답을 구조 모순으로 거절한다. 반대 방향으로 correction=fail이면 자동으로 중대 위험 플래그를 세우지는 않는다. 파서는 문장의 실제 자연스러움이나 의도를 판정하는 영어 전문가가 아니다.

참조의 노출/가족 독립성·출처 자격은 계속 별도 조건이다. 공개 진단이 개발에 노출됐다는 사실을 제품 문법 오류로 바꾸거나, 제품5차원 성공을 참조의7차원 독립성 합격으로 바꾸지 않는다.

현재 main 검토 투영은 original/meaningUsage/grammar/correctedSentence/explanation의5개 피드백 필드를 전달한다. 별도 UI의 contextNeeded 선택값·실제 추가 질문 위젯은 별도 필드로 전달하지 않는다. 설명 안에 제공된 문구는 검토할 수 있지만, 제공되지 않은 질문이나 화면 전체의 적절성을 추정해 합격으로 채울 수 없다. 전체 학습자 UI·질문 문구의 근거 연결은 T37/T38의 남은 확인 범위이며 이번 정책 연결이 이를 검증했다는 뜻은 아니다.

## 요청·응답·실행 연결

새 `product-rubric-v1.mjs`와 `product-rubric-fixture-v1.mjs`를 추가하고, 기존 ai-panel/capture-v3/panel-report-v3/panel-executor-v3의 opt-in 경로만 확장했다.

- 계약의 `productOperationalRubric`이 새 고정 정책을 요구할 때만 main review와 calibration 요청 모두에 제품용 정책 전문을 넣는다. 베이스5차원 정의의 지문도 대조한다. 참조 검토 요청에 이 정책을 붙이는 것은 거절한다.
- 새 구조화 형식은 `haru_product_operational_v1`, 응답 버전 필드는 `productRubricHash`다. 참조용 `rubricHash`와 구분한다. 기준 지문은 `1b624c1d651e5db1237976eeebf965828a476852370047733683afa20ada6b64`다.
- 새 요청은 새 응답 형식을 요구한다. 옛2필드 응답을 새 요청에 넣거나, 새 응답을 옛 요청의 점수로 재사용하면 거절한다. 지문을 되풀이하는 것만으로 이해·영어 정답·평가자 자격을 인증하지 않는다.
- 두 비생성 모델×두 표시 순서의4판정·고정 분모·불일치 보류를 유지한다. 생성 모델/버전/기대점수/다른 검토자의 표를 평가 데이터에 넣지 않는다. 응답의 중복 JSON 키와 사유 코드도 엄격하게 검사한다.
- 필수 토큰 사전 확인은 정책 전문과 새 스키마까지 포함한 전체 본문에 묶인다. 준비 검사와 실제 전송 직전 검사에서 정책의 격하를 막는다. 실제 토큰 수·요금·새 금액 승인은 아직 없다.
- 캡처는 응답 원문과 사용량을 먼저 보존한다. 지문 누락 등 계약 위반은 알려진 사용량의 회계를 보존한 채 `unknown`/보류로 남기며 재전송하지 않는다. 보정·보고는 실제 캡처의 요청 버전에 맞춰 해석한다. 옛 응답을 고쳐 저장하지 않는다.
- 현재 요구되는12개 보정 참조의 미검토/분쟁 상태는 그대로다. 그 자격 조건을 켠 현재 프로필은 새 정책이 있어도 lease·토큰 계산·생성 전에 막힌다. 성공 모의 경로는 옛 합성 메커니즘 프로필의 도구 검증이며 실제 자격 합격이 아니다.
