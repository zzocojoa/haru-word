# T34.2 — 독립 문장 가족과 짝 비교 집계

2026-11-08 · `ai-quality-v147` · phase59. 표본·집계 규칙의 개발용 구현이며 최종 위험/집계 승인이나 실제 AI 평가 합격이 아니다. 전체40개/세부133개 목표, T34/자식4개 `review`, 품질/출시 `held`를 유지한다.

## 확인한 연결 공백과 변경

기존 `report.mjs`의 `comparisons`는 문장×반복 횟수의 기술 통계이고, `riskFor`의 위험 단위는 가족 합집합이다. 현행 `panel-report-v3.mjs`는 응답별 AI 합의 상태를 제공한다. phase58 검정력은 독립 가족의 개선/악화/동일/미측정을 가정하므로 기존 문장 단위 비교를 그 표본 수로 바로 사용할 수 없다.

회귀 재현에서 같은 가족의2문장×2반복은 기존 비교 분모4였지만, 가족별 짝 비교 분모는1이다. 모델3개도 독립 가족을3개로 늘리지 않는다. 새 `family-pairs-v1.mjs`는 이 차이를 명시하고, `family-readback-v1.mjs`는 기존 합성 수집기의 물리 캡처를 읽어 새 집계를 만든다. 기존 수집기·보고서·점수·원장·요청 본문은 수정하지 않는다.

## 집계 규칙 초안

한 가족은 같은 영역/계층의 여러 변형 문장을 포함할 수 있다. 하나의 가족 ID를 영역·계층에 걸쳐 재사용하면 거절한다. 서로 다른 ID가 실제로 독립이라는 뜻은 아니며, 단어 치환·같은 틀의 별칭이나 의미상 중복은 별도 출처 감사가 필요하다.

| 범위 | 규칙 |
| --- | --- |
| 가족의 한 단계 | 예정된 모든 변형·반복이 평가됐고 모두 성공하면 `pass`; 전부 평가됐고 하나라도 실패하면 `fail`; 하나라도 미측정이면 `unavailable` |
| 개선 | 기존 가족 `fail` → 후보 가족 `pass` |
| 악화 | 기존 가족 `pass` → 후보 가족 `fail` |
| 동일 | 양쪽 모두 `pass` 또는 모두 `fail`; 두 종류를 따로 표시 |
| 미측정 | 어느 단계든 예정 문항·반복의 누락/미확정이 있으면 가족 전체의 짝 비교는 `unavailable` |
| 반복 흔들림 | 같은 문장의 여러 반복에서 성공·실패가 함께 관측됐는지 표시; 서로 다른 변형 문장의 차이를 반복 흔들림으로 세지 않음 |

가족 양쪽이 모두 실패했어도, 어떤 문장은 개선되고 다른 문장은 악화됐을 수 있다. 가족의 `tie`와 별도로 **문장별 개선·악화 수 및 혼합 변화 가족**을 보존한다. 후보의 중대 위험이 한 번이라도 관측되면 미측정 가족에서도 이를 남긴다. 가족 집계로 위험·악화 관측을 덮거나 기존 보류를 해제하지 않는다.

예정된 모든 문장·모델·단계·반복을 기준으로 빈 칸을 만든다. 빠진 칸은 삭제하지 않는다. 중복 셀·동일 캡처 재사용·알 수 없는 모델/문장/반복·가족의 계층 이동을 거절한다. 문장 가족 ID는 기존 AI panel 식별자 형식을 따른다.

6계층×3모델의18개 그룹을 항상 표시한다. 자료가 없는 계층은 예정 가족0과 이유를 표시한다. 한 그룹의 미측정 가족이1개라도 있으면 짝 비교 구간은 `null`이며 분모를 줄여 계산하지 않는다. 모두 측정됐으면 기존 `pairedEffect`의 네 단측 경계와114개 전체 배분으로 **가정에 따른 산술 구간**을 계산한다. 반복/모델/다른 계층을 합산한 표본 수로 추론하지 않는다. 전 계층 공동 합격 확률이나 실제 영어 오류율이 아니다.

## 물리 캡처와 판단 자격 구분

읽기 전용 어댑터는 현행 `inspectSyntheticPanelV3`의 recovery/원장/물리 캡처 검사를 먼저 사용한다. 합성 `pilot-panel`만 받으며 실제 평가 모드, 다른 단계, 산술 설정에 끼워 넣은 문장/관측값 덮어쓰기를 거절한다. transport나 writer session을 만들지 않으며 키·API를 사용하지 않는다.

서로 다른 두 검토 모델×두 순서의4판정이 모두 유효하고, 미확정 차원 없이 동일하며, 참조가 미해결이 아니고 보정 산술이 통과해야 기술 통계에서 측정값으로 사용한다. 그때 전원 같은 중대 위험 실패를 제시하면 기술 통계의 `fail`로 셀 수 있다. 한 판정만 중대 위험을 제시하면 위험 관측은 보존하고 짝 비교는 미확정으로 둔다. **원래 보고서의 `held-critical`·`held-disagreement`·참조/보정 자격 보류는 그대로 유지한다.** 이 기술 통계의 실패 집계가 기존 보류를 실제 합격으로 바꾸는 것은 아니다.

현행 main panel의 캡처 형식은 기존5차원/중대4개다. 이 재조회는 그 형식을 보존한다. 공개 참조의 새7차원/중대5개를 이 형식으로 절단해 재채점하지 않는다. 새 본평가의 최종 판단 스키마·평가자 자격·참조 자격은 별도 동결/검증이 필요하다. 실제 입력의 거절은 영어 실패로 자동 간주하지 않고 미측정으로 남긴다.

원장·응답 지문을 검증한 사실과 AI 판단이 옳다는 주장은 다르다. 출처 보정의 `sourceQualification`, 원래 panel 보류/상태 수·출시 판정을 함께 보존한다. `sourceProvenanceVerified`, 가족 독립성, AI 영어 품질, 최종 규칙 승인, 실평가 준비와 출시 자격은 `false`다.

## 재현 및 무결성 검증

- 같은 가족2문장×2반복: 기존 문장 분모4/새 가족 분모1을 실제 기존 보고서 호출과 대조한다.
- 혼합 개선/악화, 양쪽 실패, 예정 반복 누락과 동시에 관측된 중대 위험, 반복 흔들림, 중복 캡처·셀·가족 계층 이동을 검사한다.
- 과거 phase25의1872슬롯/360생성 캡처는 동결된 Node22.23.4에서 재조회한다. 60가족/180모델별 가족 비교이며, 기존359합의성공+1불일치를 보존한다. 불일치가 속한 짝1개는 미측정이고 해당 계층 구간을 계산하지 않는다. 과거 파일/원장 전후 전체 지문을 대조한다.
- 다른 Node 버전에서 같은 과거 캡처를 읽으면 기존 runtime binding이 거절해야 한다. 처음 Node24에서의 `R3_PHYSICAL_CAPTURE_REQUIRED`를 직접 캡처 reader로 좁혀 `C3_ACTUAL_RUNTIME`임을 확인했다. 동결 Node22에서는 모든1872개 캡처를 읽었다. 검사 강도를 낮추거나 환경을 위조하지 않는다.
- 각 Node에서 새로 만든102슬롯 물리 캡처는 전원 동의한 중대 실패와 한 표의 중대 불일치를 구분한다. 재조회가 파일을 바꾸지 않음을 확인하고, 응답 바이트 변조는 재조회 거절/추가 전송0으로 남긴다.
- 최초 테스트의11개 중2개 실패(위의 runtime 불일치와 테스트 응답의 미지원 `meaning` 사유 코드)를 원본 코드·수집 자료와 함께 보존했다. 사유 코드는 기존 허용값 `meaning_preservation`으로 고쳤으며 parser/보류 조건은 변경하지 않았다. 최종 결과는 phase59 실행 로그를 따른다.

사용 예 — 이미 존재하는 합성 bundle/context에서 조회만 수행한다.

```js
import {inspectSyntheticFamilyPairsV1} from './.taskmaster/scripts/ai-quality-v147-family-readback-v1.mjs';
const report = inspectSyntheticFamilyPairsV1({
  context, seal: bundle.seal, observeCurrent: () => bundle.current,
  reportInputs: bundle.reportInputs,
  arithmetic: {familywiseConfidence: .95, boundCount: 114, minimumImprovement: 0}
});
// report.groups: 모델/계층별 가족 수, 네 범주, 미측정 사유와 조건부 구간
// report.collection: 기존 캡처/자격/보류 근거. releaseEligible은false.
```

SOURCE의 새 검증은 `node --test .taskmaster/scripts/test-ai-quality-v147-family-pairs-v1.mjs`다. 기존 보고서/위험/검정력 회귀도 관련 근거로 확인한다. 실평가용 transport, 토큰 계산, 본문 재전송, 원장 재개/정산/쓰기, 운영 QA나 배포를 실행하는 도구가 아니다.

## 남은 완료 조건

이 가족 성공 규칙은 개발용 초안이며 최종 채택이 아니다. 실제 가족 출처·계층·대표성·의존 관계와 규칙 적합성을 확인하고, 자격을 갖춘 AI 평가자의 예비 결과로 개선/악화/누락 가정을 정해야 한다. 그 뒤 최종 위험/MDE·검정력/N/r·새 본문/스키마·실측 입력 토큰 견적과 사전 등록을 확정한다. 표본을 늘려 기존 악화나 미측정을 희석하지 않는다.
