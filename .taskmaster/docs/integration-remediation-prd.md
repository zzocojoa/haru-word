## 문제와 대상 사용자

새 방문자는 로그인할 수 있어야 하고, 작성 중인 입력은 실패해도 보존되어야 한다. 현재 로컬 최신 소스에서는 익명 상태 조회의 정상 401이 계정 무효화로 전파되어 로그인 링크를 가린다(I00). 브라우저 에이전트 요약은 저장 실패한 목표도 저장된 값으로 알려준다(I03). 설치된 의존성과 lockfile 불일치(I01), 제품 결함·준비 조건·옛 계약이 섞인 브라우저 검사(I02), 운영 문서의 현재/과거 구분 불일치(I04)도 확인됐다.

대상은 비개발자인 앱 사용자와 이 프로젝트를 이어 수정하는 개발 에이전트다. 결과는 쉬운 한국어로 설명하고, 실행 증거는 별도로 보존한다. 운영에서 같은 결함을 직접 재현했다고 주장하지 않는다.

## 관측 가능한 성공 조건

1. 익명 첫 진입과 새로고침에서 로그인 링크가 보이고, 반복 새로고침만 요구하지 않는다. Chromium/WebKit에서 확인한다.
2. 로그인 만료·계정 전환에서는 이전 계정의 폼·초안·위치 요청을 차단한다. 익명 진입 복구를 위해 계정 보호를 약화하지 않는다.
3. `get_learning_summary`의 값은 마지막 서버 확인 스냅샷과 일치한다. 저장 전·진행 중·503·409에는 이전 확인값, 성공 응답 후에는 새 확인값을 반환한다. 화면의 미저장 입력은 보존한다.
4. 현재 lockfile을 변경하지 않고 재현 가능한 설치·빌드를 만든다. 알려진 source-map-js/sharp 불일치를 포함한 직접 설치 의존성 점검과 실제 버전을 기록한다.
5. 기존 원본 브라우저 검사 84조건을 추적한다. 검사 이름을 삭제하거나 묶음을 줄여 통과시키지 않는다. 문법 v2/v3/v4는 맞는 프로필에서 검사하고, 프로필별 검사를 분리하면 원래 조건과의 매핑을 남긴다.
6. 생성 POST와 상태 GET을 구분한다. 현재 AI 문맥·모델·요청 UUID/영수증 계약의 합성 응답과 과거 저장 의견 fixture를 분리한다. 옛 계약 보호를 제거하지 않는다.
7. 단어/문법/뜻별 진도·첫 답·현재 입력·백업·revision·한국 날짜·과거 AI 의견이 보존된다. 전체/분할 복원의 한도·원자성·불확실 결과 재조회는 그대로다.
8. 작업·검증·미확인·배포 상태를 구분한다. 과거 두 플랜의 15/35·18/49와 당시 예산/점수는 새 플랜에 합치지 않는다.
